# Smart Library 设计规范（v0.3）

技术路线：Tauri 2 + Rust + Tantivy + SQLite，仅桌面端。
本文由设计会话整理而成，是代码仓库中的唯一规范来源（会话中的 Claude Doc 草案 v0.1 已并入此处并修正）。
标注「待确认」的内容是尚未用数据验证的假设。

## 0. 摘要：只有三个核心抽象

- **统一节点（Node）**：藏经的一卷、Wikipedia 的一篇文章、一个文件、一条笔记，结构完全相同：有名称、有父级，可能有内容，可能有子级。差别只在于有没有内容、有没有子级。
- **仓库适配器（Adapter）**：把任意数据源（zip、目录、Wikipedia 包、自维护库）统一成这种节点树，按需提供子节点、内容和可索引文本。
- **定位器（Locator）**：搜索命中后如何回到具体位置，由适配器自己定义和解释，核心与界面只负责传递，不关心内部格式。

各数据源专属的阅读功能（卷的同级导航、经内大纲、校勘注释）不进入节点模型，由适配器以**可选扩展**提供（见第 9 节）。目录树、全文搜索、标题快搜、导出、阅读，都是这三者的组合；新增一种数据源，只需要多写一个适配器。

## 1. 目标与非目标

**目标**

- 把多种来源的资料组织在同一棵目录树下，统一浏览、统一搜索。
- 搜索是核心体验：精确、快速、可限定范围、可分面、可导出、可定位。
- 启动快、安装包小、不依赖外部服务（不装 JVM、不起 Solr）。
- 只读仓库永不修改源数据；自维护仓库可读写。

**非目标（初期）**：手机端、多人协作与云同步、修改 Obsidian 等外部库的数据、通用富文本或排版编辑器。

## 2. 术语

- **知识库（Library）**：目录树里的每个根节点就是一个知识库（目录树没有唯一的总根）；反过来，知识库只出现在根节点这一层。它是绑定、建索引、限定搜索和快搜范围的单位。一个数据包可以提供多个知识库（bookcase 的 CBETA 一棵树加各自加树，见 9a）。
- **仓库（Repository）**：一个数据源，由一个适配器负责读取；它向目录树提供一个或多个知识库。
- **节点（Node）**：目录树中的一项，也是阅读和检索的基本单位。有没有内容、有没有子级是两个独立属性。
- **内容节点**：有内容的节点。全文索引只针对内容节点，标题快搜针对所有节点。
- **范围（Scope）**：用户在目录树中勾选的一个或多个节点，用于限定搜索。
- **命中（Hit）**：一次搜索结果，包含节点、摘要和定位器。

## 3. 总体架构

自上而下四层：

1. **界面层**：Tauri 窗口。左侧目录树，右侧单个 Webview 内容区，另有搜索面板和标题快搜浮层。前端用 Vue 或 Svelte，Node 只在开发时使用。
2. **命令层**：Tauri 的 commands 与 events，只做参数转换，返回 JSON，不含业务逻辑。
3. **核心库 core**（纯 Rust，不依赖界面）：仓库管理器、适配器接口及实现、索引器、搜索服务、标题索引、后台任务队列。
4. **存储层**：SQLite（注册表、设置、笔记）、Tantivy 索引目录、各数据源本身。

工程组织为 Cargo workspace：`core`（库）、`cli`（命令行，开发期验证）、`app`（Tauri，之后加入）。**先让 core 加 cli 跑通，再接界面**，这样每一步都能独立测试。

## 4. 节点模型

**节点 ID**：全局唯一，形如 `仓库ID:本地ID`。本地 ID 由适配器决定，但必须稳定（数据更新后不变）。例如 CBETA 用经号和卷号，文件系统仓库用相对路径，笔记库用 UUID。

**节点字段（草案）**

- `id`、`parent_id`、`position`（同级排序）
- `name`：标题；`aliases`：别名列表（异名、简称、译名等），参与标题快搜
- `description`：简短说明或摘要
- `contributors`：作者、译者、编者等，每项含姓名和角色
- `attributes`：键值对，存放各数据源的专属信息（朝代、册号、原书页码、标签、创建时间等）
- `content_type`：内容类型（HTML、Markdown、纯文本、PDF、媒体等），无内容时为空
- `has_content`、`has_children`：由适配器按需给出，不必为了判断而加载全部内容或全部子节点
- `content`：正文本身。只读仓库不在节点里存放，通过 `content(id)` 按需读取；自维护库存放在 SQLite 中

**不区分卷、文章、文件、笔记**：它们是同一种节点。有子级时，目录树把它显示为文件夹；无内容时，在 Webview 中打开为空白（可写仓库可直接开始编辑）或不允许打开（只读仓库）；既有内容又有子级时两者兼有（Everything is a Note，借鉴 Trilium）。节点上没有 `kind` 字段，图标等展示需求由 `content_type` 和是否有子级推出。

**索引粒度由此自然得出**：全文索引针对所有有内容的节点。CBETA 里只有「卷」有内容，「经」只是带元数据的目录节点，所以按卷索引；本地目录里每个文件是一个内容节点。粒度完全取决于适配器让哪些节点有内容。

**懒加载**：目录树按需展开，`children(parent)` 每次只返回一层。Wikipedia 这类百万级节点的仓库不可能一次构建整棵树。

**多棵树**：一个仓库可以提供多种组织方式。例如 CBETA 官方的 bookcase.zip 里有 3 棵目录树（用户的数据包可以另加，见附录 A.3），适配器通过 `trees()` 暴露它们，用户设置默认使用哪一棵。

## 5. 适配器接口（草案）

```rust
trait Repository {
    fn info(&self) -> RepoInfo;                    // 名称、类型、能力声明
    fn trees(&self) -> Vec<TreeInfo>;              // 可用目录树，至少一棵
    fn children(&self, tree: &TreeId, parent: Option<&NodeId>) -> Result<Vec<Node>>;
    fn node(&self, id: &NodeId) -> Result<Node>;
    fn content(&self, id: &NodeId, opts: &RenderOpts) -> Result<Content>;
    fn index_nodes(&self) -> Box<dyn Iterator<Item = Result<IndexNode>> + '_>;  // 有内容的节点，供建索引
    fn fingerprint(&self) -> Result<String>;       // 数据版本指纹，变化则提示重建
    fn locate(&self, node: &NodeId, q: &ParsedQuery) -> Result<Vec<Hit>>;     // 节点内命中位置
    fn cite(&self, hit: &Hit) -> String;           // 导出用的引用文本

    // 可选扩展，默认实现返回空
    fn outline(&self, id: &NodeId) -> Result<Vec<OutlineItem>> { Ok(vec![]) }  // 节点内标题大纲
    fn view_options(&self) -> Vec<ViewOption> { vec![] }                       // 阅读选项：简繁、分行、注释
}

trait Writable: Repository {
    fn create(&self, parent: Option<&NodeId>, draft: NodeDraft) -> Result<Node>;
    fn update(&self, id: &NodeId, patch: NodePatch) -> Result<()>;
    fn delete(&self, id: &NodeId) -> Result<()>;
    fn move_to(&self, id: &NodeId, new_parent: Option<&NodeId>, pos: usize) -> Result<()>;
}
```

要点：

- 适配器**不依赖 Tantivy**，只负责提供数据和位置。索引器、搜索服务是独立模块。
- `IndexNode` 包含：节点 ID、名称、别名、纯文本正文、贡献者、属性、分面路径列表、语言。
- `Content` 的类型：HTML、Markdown、原始文件（PDF、图片、音视频）、无内容。
- 只读仓库只实现 `Repository`，可写仓库再实现 `Writable`，界面按能力决定是否显示编辑入口。
- 可选扩展有默认实现，界面据此决定是否显示对应的面板。

## 6. 各类仓库的适配要点

### 6.1 CBETA（bookcase.zip，只读）

- 用 `zip` crate 随机读取，不解压，更新时直接替换 zip。数据源格式见附录 A。
- 节点：册、部类等为目录节点；「经」是带元数据（作译者、朝代、典类）的目录节点；「卷」是有内容的节点，也是唯一被全文索引的节点，所以索引粒度为卷。
- 数据装配：`bookcase.zip` 不能直接遍历 XML 使用，要先把 `catalog.txt`、`bookdata.txt`、三棵 `*_nav.xhtml` 和每部经的 `toc` 文件串起来（附录 A.2–A.4）。适配器启动时装配成内存中的目录与元数据表，并按 zip 指纹缓存，卷 XML 本身仍按需随机读取。
- 元数据与分面：典类、人物、时域来自人工整理的 `data/bookinfo.json`（附录 A.5）。
- 卷内定位：打开或展示结果时，实时解析该卷 XML，得到「纯文本 + 偏移量到原书行号的映射」，扫描所有命中偏移，再转成行号。不保存任何衍生数据。
- 阅读扩展：同一部经的各卷导航由目录树得出；经内标题大纲用 `outline`（数据来自 toc 文件）；简繁切换、原书分行、校勘与注释的显示用 `view_options`。
- 指纹：zip 的大小与修改时间，加 `index.xml` 的版本与日期。
- 简繁、异体字、缺字的归一化在统一的归一化管线中处理，原文保持不动。
- 使用前需核对 CBETA 的授权条款。

### 6.2 本地目录（资料目录、Obsidian 库，默认只读；读写模式见 6.5）

- 子节点即真实目录与文件；每个文件是一个有内容的节点。
- 文本和 Markdown 直接读取；PDF、docx、epub 等需要文本提取（依赖库待评估）；媒体文件提取时长、编码、标签等元数据后建索引。
- Obsidian 库按 Markdown 目录处理，可额外解析 frontmatter、标签和双向链接作为元数据，全程只读。
- 变更检测：比较路径、修改时间、大小，做增量索引；文件监视作为可选功能。

### 6.3 Wikipedia 离线包（只读）

ZIM 适配器：绑定 ZIM 5.0 数据包，按文章标题快搜或手动建立全文索引，不展开目录。支持未压缩和 Zstandard 簇，读取时解压单簇并缓存；单簇解压上限 256 MiB。文章正文复用现有安全 HTML 阅读器，支持段落、章节及部分包内图片。段落视图中包内文章链接可点击，支持相对路径、重定向和章节锚点；目标缺失时提示。其他格式版本和压缩方式暂不支持。源文件改变后索引失效，需要重建。源数据始终只读。已用中文 Wikibooks 2023-01 和 Wikiquote 2021-11 数据包验证读取和全文索引。

识别 ZIM HTML 中 `htdig_noindex` 标记包围的版权声明，从正文和全文索引中分离；阅读器在文末单独显示该篇的原始声明文字。无法确认是声明的内容保留在正文。更改此抽取规则后仅 ZIM 索引需要重建；ZIM 标题不提供目录树定位，空的文章选择框不显示。

ZIM 正文中，HTML 的二至六级标题若完整文本为「语录」「参考文献」「参见」（繁简均可），仅从全文索引和命中定位中排除；仍显示在正文和目次中，正文里的同名文字与其他标题仍参与搜索。屏蔽位置保留原字符偏移，并在分词位置中断开，避免高亮错位或跨标题错误匹配。此规则调整后需要重建 ZIM 索引，其他类型的索引不受影响。

维基跨库链接：ZIM 使用通用知识库 ID（例如 `wikipedia`）关联站点；新建时指定，创建后不可更改。旧版本已设置的维基关联继续有效，不改变已有知识库 ID。匹配 `*.wikipedia.org`、`*.wikiquote.org`、`*.wikibooks.org` 等维基站点的文章链接，先按站点名称找到对应 ID 的库，再按文章路径和重定向查找，找到后打开并定位章节。其他 HTTP(S) 链接或本地找不到的目标可在系统浏览器打开，默认每次询问，也可以记住直接打开，并能在设置中改回询问。不执行网页脚本或允许其他协议。

知识库创建或绑定时可指定 ID；只能以小写字母或数字开头，后接小写字母、数字、连字符或下划线，最多 64 位且不可重复；留空自动生成。库根节点也可设置属性，过滤属性及正文索引设置向下继承，下级可覆盖。正文可设为继承、索引或不索引；标题和过滤属性始终索引。标题加入全文索引后索引版本为 5，旧索引需重建。

- 据我所知，常见的离线形式是 Kiwix 的 ZIM 文件：可随机读取，内含压缩的 HTML 文章和标题索引。这一点需要确认实际使用的是哪种包。
- 它本质上更像「按标题排列的扁平文章集合」，不是真正的目录树。树可能要虚拟构造（首字母、分类等）。
- 几十 GB 的规模下，建索引的耗时和体积需要实测，可能需要「只索引标题」或「只索引摘要」的降级模式。

### 6.4 自维护知识库（读写）

- 存储：SQLite。核心表 `notes`：`id`、`parent_id`、`title`、`content`、`content_type`、`position`、`created`、`updated`、`attributes`。树由 `parent_id` 和 `position` 构成。
- 内容格式：建议以 Markdown 为主，保持简单、可导出、可检索。
- 写入流程：先写 SQLite 事务，成功后向索引器发出变更；索引器合并变更，约每秒批量提交一次。**以 SQLite 为准，索引随时可以重建。**
- 初期不做 Trilium 的「克隆」（一个节点挂在多个父节点下），以降低复杂度。
- 「我的日记」是同一种适配器的另一个实例，不需要单独实现。

### 6.5 可编辑的文件夹库（读写模式；第一步已实现，待用户点验）

目的：让挂载的外部文件夹也能编辑笔记，数据全在目录和文件里，可用 git 同步备份。编辑器（Milkdown、Mind-Elixir、Excalidraw）原样复用，只是存取从 SQLite 换成读写文件。

- **只读 / 读写开关**：每个文件夹库一个，默认只读。从只读切到读写必须经过确认对话框（添加向导里和库属性里切换时都要弹），文字写明：软件会修改、新建、重命名、删除文件；Markdown 经排版编辑器保存后格式可能被规范化；建议先用 git 或备份。
- **开关存本机应用数据，不进库目录**。这样别人 clone 仓库后不会自动变成可写，每台机器各确认一次。
- **类型按后缀识别**（改回只读后这三种文件仍列在树里，脑图和白板以其中的文字显示）：`.md` → Markdown，`.map.json` → 脑图（Mind-Elixir），`.wbd.json` → 白板（Excalidraw）。只允许编辑本程序保存的格式；其他文件（HTML、txt、PDF 等）仍然只读。
- **写入规则**：只有内容真的改了才写盘（打开不写）；先写临时文件再改名；路径必须限制在库根目录内；保存前比对修改时间，发现文件在外部被改过就提示，不直接覆盖（不做文件监听）；Markdown 的 front matter 作为纯文本整块保留。使用者预期不与其他笔记软件混用，故不追求对 wikilink 等语法的往返保真，但提供源码模式作保底。
- **元数据侧车 `.smart-library/meta.json`**（`core/src/sidecar.rs`；已实现）：读写库的节点属性（部类 / 时域 / 人物 / 藏经 / 典类）、书签、收藏、节点标签随文件夹走。程序自己的 SQLite（`props.db`、`marks.db`）仍是工作副本，文件是随文件夹走的那份：每次属性 / 标记变化、移动、重命名之后写文件（内容没变则不写），打开库时（第一次用到文件夹库）用文件替换工作副本里这个库的数据。从只读切到读写时合并两边（文件里有而本地没有的加进来），再写文件。格式：`format`、`version`，`props` 与 `marks` 各一条记录一行、按路径等排序，git 差异和合并小。键是库内相对路径，库名等本机信息不写。是否提交由用户用 `.gitignore` 决定。「最近打开」留在本机。扫描和建索引跳过 `.smart-library/`。在软件内重命名 / 移动时，属性、标记、最近打开的路径一起改（`rekey`，文件夹连同里面的文件）；在软件外改名则这些数据对不上，接受。只读库仍把这些存在应用数据里。
- **附件**（已实现）：图片集中放在库根的 `.smart-library/attachments/`，名字是内容的 32 位指纹加 8 位随机数（粘贴一次就是一个自己的文件，同一张图粘贴到两篇笔记也是两个名字；内容相同的（指纹相同，在同一个分级文件夹里找前 32 位相同的文件）后来的是先来的那个的硬链接，磁盘上只占一份，不支持硬链接时才复制），再用名字前 4 个字符分两级文件夹（`5c/99/…png`）。显示图片只认文件名（编辑器里是 `attach:<名>`，不看路径）。Markdown 文件里写相对链接 `![](../.smart-library/attachments/5c/99/<名>.png)`（`../` 层数随笔记所在文件夹），别的软件也能显示；打开和保存时与 `attach:` 互转（`folder::to_editor`、`FolderLibrary::prepare_save`）。清理：保存笔记时，上次保存里引用、这次不再引用的图片进回收站（编辑器里撤销会带回链接，图片从回收站找回并在下次保存时放回）；删除笔记或文件夹时，其中的图片和只有它们用的图片进回收站；设置里的「清理缓存」清空回收站并删除没有任何笔记引用的图片（最近一分钟内的除外）。移动笔记或文件夹时，里面 Markdown 的链接按新层数重写。内部知识库的图片仍按内容去重，只在「清理缓存」时清理。脑图里的图片仍记为 `attach:<名>`，白板的图片仍内嵌在 JSON 里。只读模式的阅读器也显示这些图片（带标题的 `![](… "标题")` 也认）。早期版本的图片（笔记旁 `.assets`、平铺在 attachments）保存时自动搬到新位置。
- **拖放**（已实现）：内部库的笔记可以拖到另一篇笔记上（成为它的最后一个子笔记）或知识库行上（放到顶层），多选一起拖，不能拖进自己里面。落在行的上四分之一 / 下四分之一是放到它前面 / 后面（可调顺序，行上画一条线），中间一半才是放进它里面。把一个或多个选中的节点拖到文件夹行、文件行（放进它所在的文件夹）或知识库行上就是移动；拖动时实时判断：落点没有变化（已在那里、在自己里面）或已加载的目标里有同名时，目标画虚线框、鼠标变成禁用标志，松手无效；目标还没读过的文件夹无法预先判断，失败时用提示说明。阅读器或编辑器里选中的文字可以拖到可写知识库（内部库或读写本地文件夹）的节点上：弹出名称框（默认取第一行），用这些文字新建 Markdown 笔记（放在该文件夹或该笔记之下，文件行则放在它旁边）并打开。
- **回收站**（2026-11）：读写本地文件夹删除的文件和文件夹移到 `.smart-library/trash`，同时在 `.smart-library/trash.json` 记下每项的 `entry`（回收站里的名字）、`rel`（原来的相对路径）、`kind`（`file` / `dir` / `picture`）和删除时间。这个索引只是帮助恢复：文件丢了索引仍能从回收站列出，旧版本的 `<时间>-<名>` 条目按顶层恢复。目录树右键知识库 →「回收站…」（`TrashDialog.svelte`）列出文件和文件夹（图片不单列，随使用它的笔记回来），可逐项或全部恢复：先建好上级文件夹，再把内容移回原路径；原路径已有同名文件夹时逐层合并进去（不建「b 2」），只有同名的文件用 `名字 2`、`名字 3`，不覆盖。恢复后会读出其中 Markdown / 脑图 / 白板引用的图片名，把还在回收站里的对应图片移回 `.smart-library/attachments/…`。恢复的文件记入「待索引」；属性在删除时已从侧车移除，不随恢复回来。设置 →「数据清理」的清理缓存连同 `trash.json` 一起清空。内部知识库的笔记不进这个回收站，它们有自己的笔记回收站（见 6.4）。
- **目录树操作**：文件夹库（和所有只读库）的节点禁用上移 / 下移，顺序按文件名。读写模式下可在库根、文件夹里、文件旁「新建文件夹」（同样受文件名约束，`FolderLibrary::create_dir`）；文件夹节点点击只展开，不打开阅读器。内部库的笔记本身可以有子笔记，暂不需要另设文件夹类型。删除走回收站或库内 `.trash`，不直接硬删。
- **文件名约束**（新建、重命名、新建文件夹都适用，跨平台一律按最严格的执行）：不允许 `\ / : * ? " < > |` 和控制字符；不能以空格或点结尾；不能用 `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9` 等保留名；长度有上限；同目录重名忽略大小写比较。后缀固定，重命名时只改主名。输入时实时校验，旁边显示「本地文件名限制」提示。自动取名「笔记 n」走同一套校验。
- **索引**：保存时不更新索引。被改动的文档（保存、新建、重命名、删除，内部库也一样）记入「待索引」集合，**在全文搜索开始前**成批写入索引（`AppState::flush_dirty` → `search::sync_docs`：存在的重写，已不存在的删除，内部库同时记下新的数据版本）；没有建过索引、或正在重建时跳过，重建会清空该集合。所以不管怎么编辑，用到全文搜索之前索引与否没有区别。标题快搜的缓存保存后作废重建。
- **分步**：第一步（已实现）= 开关与确认（添加向导的勾选、右键菜单「改为读写模式…」，开关存 `libraries.json` 的 `writable`）、三种类型的编辑与自动保存、新建 / 重命名 / 删除（回收到 `.smart-library/trash`，可在「回收站…」里恢复）、保存前的修改时间比对（`FolderLibrary::stamp`）、文件名约束（`folder::check_name`，前后端共用同一函数）。第二步（已实现，待点验）= 侧车元数据、粘贴图片的附件、文件夹和文件的重命名 / 移动（右键「移动到…」选目标文件夹，`FolderLibrary::move_to` / `rename`；关闭里面已打开的标签、改名、再打开）、改名 / 移动时属性与标记的键同步。第三步（已实现，待点验）：删除文件夹（进回收）、新建文件夹时可输入 `甲/乙/丙` 一次建多级、拖放移动（把一个或多个选中的节点拖到目录树里的文件夹行、文件行或知识库行上）、设置里的「清理缓存」（清空读写本地文件夹的 `.smart-library/trash`，删除没有笔记引用的图片，内部知识库的图片也一样）。**目录树与磁盘同步**：窗口重新获得焦点时（延迟 0.3 秒）、以及每次展开已读过的文件夹时，把显示的内容和磁盘比对，消失的节点移除、新增的加入，已展开的文件夹保持展开（按相对路径重新对应展开状态）；侧车文件被外部改过（git pull）时也在获得焦点时重新读入。不另外锁定侧车文件（锁住会让 git 操作失败）。**切换锁定 / 解锁**只是库的一个状态，目录树不重建；已打开的阅读标签关闭后重新打开。**导入知识库包**到内部库后，新笔记记入「待索引」，库已有索引时在下一次全文搜索前自动补进，没有索引就等用户建立。**未做**：外部改名 / 移动 / 删除的笔记，属性和标记仍对不上（用户在软件外的操作）。
- 实现位置：`core/src/folder.rs`（`EditKind`、`check_name`、`write_edit` / `create` / `rename` / `delete`）；`app/src-tauri/src/commands.rs`（`save_note`、`rename_note`、`delete_note` 对文件夹库分支，新增 `create_folder_file`、`set_folder_writable`、`check_file_name`）；前端 `writable.js`（确认文字）、`LibraryPanel.svelte`（菜单）、`NameDialog.svelte`（实时校验与提示）。前端用阅读结果里的 `raw` 是否存在判断能否编辑。

## 7. 索引设计

**每个仓库一个独立的 Tantivy 索引目录**，不做一个全局大索引。理由：

- 各仓库规模差异极大（藏经几百 MB，Wikipedia 几十 GB），独立索引便于单独重建和删除。
- 各仓库可以有不同的分词与归一化策略。
- 导入或移除仓库互不影响。

**通用字段**：`node_id`、`name`、`aliases`、`body`（只索引，不存储）、`contributors`、`path`（层级分面）、`lang`，以及各仓库自定义的属性字段（朝代、册号等）。只有内容节点进入全文索引。

**默认分词器 `aio`，所有仓库共用**：沿用 cbeta-explorer 在 Solr 中验证过的 `text_aio` 组合，即标准分词（拉丁文按词，汉字逐字）、全半角折叠、小写、CJK 二字组。混合文字实测没有问题，所以各仓库默认共用，需要时再单独覆盖。

对旧 Solr 实现的实测结果（用 cbeta-explorer 验证）：

- 单字查询可以命中（旧界面搜「念」得到 904 条结果），所以新分词器必须支持单字。旧界面的文档粒度看来是章节（结果标题是『念』这样的章节名），与新实现的「卷」不同，条数不可比：新索引里含「念」的卷有 18407 个。
- 默认查询是**宽松匹配**：各二字组出现在同一内容节点内即可命中，不要求相邻（见 8.3）。

**M0c 的实现**（`core/src/analyzer.rs`、`core/src/search.rs`）：

- 字符折叠：NFKC（全半角、兼容汉字）、小写、**繁体到简体**（`data/t2s.txt`，2734 对，一字对一字，取自 fast2s，MIT）。索引和查询、命中定位三处用同一个折叠函数，原文不变。代价：少数不同的繁体字会合并（乾、幹都到「干」，於到「于」），对宽松检索可以接受。异体字：`data/variants.txt`（`异体 正字`，约 35 对：日本新字体和通用异体，如 説→說、経→經、蹟→跡）先换成正字再转简体，所以 説、說、说 同一个结果；表里只放确定无歧义的字，改动后要加大 `INDEX_VERSION`（现为 5）重建索引。
- 字符分类：CJK（汉字各区、假名、谚文、PUA 缺字、〇 々 〡）连成一段；标点和空白是**透明**的，不打断汉字段（二字组跨逗号，与卷的 `plain` 一致），但会结束拉丁词；其他符号（○ △ ─ 等）打断汉字段；字母数字连成一个词。
- 两个字段：`body` 放二字组、拉丁词和单字段（长度为 1 的汉字段），**带位置**，用于短语；`body1` 放所有单字，**只有词频没有位置**，因为单字查询永远不需要位置。这样单字不必付出位置信息的体积。
- 一卷一个文档，索引的是带标点的 `text`（标点透明，空白仍能分开拉丁词）。另有 `path`、`book`、`juan`、`title` 存储字段和一个 `facet` 字段。
- 2025.Q1 实测：21233 卷（LC、Y 不收），建索引约 43 秒，索引 761 MB；单字「念」搜索 25 ms，短语「如是我聞」8 ms；命中定位每卷约 1–3 ms。
- 索引目录默认 `app_data/repos/cbeta/index`，里面的 `smart-library-index.json` 记录索引版本（`INDEX_VERSION`，分词器或字段变化时加一）和数据版本；版本不符时要求删除重建。

Tantivy 的实现要点（设计时的预估，已按上面实现）：

- Tantivy 没有现成的 CJK 二字组过滤器，也没有 UAX#29 标准分词器，需要实现一个自定义分词器（预计一两百行 Rust）：拉丁文按词切分并转小写，汉字连续段输出单字和二字组，并给每个词元正确的位置，因为短语查询依赖位置。可借助 `unicode-segmentation` 判断词边界，用 `unicode-normalization` 的 NFKC 完成全半角折叠。
- Solr 里的同义词过滤器（`SynonymGraphFilter`）在 Tantivy 中没有现成实现，改在查询构建层做：把词展开成 OR 组。
- Lucene 与 Tantivy 的性能差异（Lucene 平均约快 1.5 倍，均为亚毫秒到毫秒级）对本项目规模无实际影响，选型依据是语言、体积和启动速度。

**归一化管线**（繁简、异体字、标点）在索引和查询两侧必须使用同一套。字级别的繁简和异体字映射建议放在索引侧，原文保持不动；查询侧的同义词展开只用于词级别，因为字级别展开会让 N 个字的查询膨胀成各变体的乘积。

**标点**：古籍用户输入的短语通常不带标点，索引时忽略标点，并保留位置映射，这样跨逗号的短语也能命中。CBETA 的标点是后加的一层（附录 A.6），去掉标点后偏移与原书行内位置一致。

**索引更新**

- 只读仓库：导入时全量建索引；`fingerprint` 变化时提示重建；目录类仓库支持增量。
- 自维护仓库：随写入实时增量更新。
- 所有索引任务进入**后台任务队列**：有进度事件、可取消、可断点续建，界面不能被阻塞。

## 8. 搜索

**8.1 范围限定**

用户在目录树中勾选一个或多个节点，系统把它们解析为「仓库 → 过滤条件」。过滤基于文档的 `path` 层级分面（例如 `/藏经/大正藏/阿含部`），按前缀匹配。一个文档可带多个 path，以兼容仓库的多棵目录树。

**8.2 跨仓库排序**

不同索引的 BM25 分数不可直接比较（统计基数不同）。默认**按仓库分组展示**，组内按分数排序；需要混排时，用 RRF 之类只看名次的融合方法。

**8.3 匹配模式**

- **宽松匹配（默认）**：把查询切成二字组，**要求全部词元**出现在同一个内容节点内，不要求相邻，按 BM25 排序，适合只记得大概的用户。cbeta-explorer 的设计理念就是不要求输入与原文完全一致的字句。已用旧截图验证：「他念摄之令常在像」只命中《坐禪三昧經》卷一，片段分散，与旧界面一致。
- **查询里的空格分隔关键词**：宽松匹配时 `比丘 他念` 是两个关键词，不产生跨空格的二字组「丘他」；精确短语忽略空格。文档里的空白则始终透明。
- **精确短语**：要求词元按顺序相邻，依赖位置信息。
- 另有邻近（A 与 B 相隔 N 字内）、排除词、字段限定，正则放到后期。

**8.4 结果与分面**

命中包含节点、路径、摘要片段和定位器，另附分面计数（按部类、朝代、作译者等）。**计数单位：分面计数是命中卷数**；总数同时给出命中卷数和命中经数（经数来自 `/book/经号` 分面的子项个数）。每卷的出现次数在定位时得到。

M0c 的分面根：`/bulei/部類/子類`（层级）、`/canon/藏经名`、`/kind/典类`（「论：经释」拆成两级）、`/period/朝代`、`/person/人物`，后三者来自 `data/bookinfo.json`（已嵌入程序）；表里没有的经暂时没有这三项。注意父级计数可以大于子级之和：有的经只有部類没有子類（如 F 藏）。

**分面值在建索引时就写成正式名称**（`INDEX_VERSION` 3）：`/canon/` 下是 `bookdata.txt` 里的藏经名（「大正新脩大藏經」），不再是代码 `T`，界面不需要维护对照表，别的数据源只要写出自己的名称就能用。建索引时还把两层维度（部类、典类）的第一层名称记进 `smart-library-index.json` 的 `facet_tops`，因为 Tantivy 的分面收集器一次只数一层，要数第二层必须事先知道有哪些父级。

**8.4a 全文搜索页（多标签、多选过滤）**

全文搜索是工作区里的**搜索页标签**（`app/src/lib/SearchPage.svelte`，标签 id `search:<n>`），可以开多个、分栏、浮动、在新窗口打开（`SearchWindow.svelte`，窗口里可「停靠回主窗口」），与阅读标签一样；搜索页的状态（词、模式、范围、过滤、页码、所选知识库）保存在标签的参数里，重启后恢复并重新搜索，窗口形式的搜索页不保存。Ctrl+H、工具栏按钮和阅读器右键的「搜索…」都是新开一个搜索页（有一个还没用过的空页时直接用它）。

- **搜索框在页内**：搜索词、「模糊 / 精确」切换、「搜索」按钮。改词（Enter）、改模式、改范围、改过滤，都会让过滤器、结果列表、页码一起重新计算。**词可以留空**：空词是 `AllQuery`，列出范围内全部文档（不取片段），用来浏览，再靠过滤和范围缩小。
- **左侧是标签页，不再从上到下堆叠**：部类、时域、人物、藏经、典类各一页，外加「范围」（有内容时标签后带 `*`）。每一页是复选框列表，**可多选**；标签上显示该维度已选个数。无值的维度（如文件夹知识库没有时域）不显示。
- **过滤语义**：同一维度内的多个值是「或」，不同维度之间是「且」。计数时某个维度**不带它自己的过滤**，所以已选的维度仍能看到其他可选值并加选；父类与子类并列显示（`华严部类` 与 `华严部类/华严部`），选父类已含子类。已选但当前无命中的值保留（半透明）以便取消，结果上方还有可点 × 的过滤标签和「清除过滤」。没有过滤的维度共用一次主查询，有过滤的维度各多一次查询。
- **大列表**：每页列表只渲染可见的行（行高固定，滚动时换窗口）；页顶有「在 X 中查找」输入框；可按「数量」或「拼音」排序（每个维度各自记住，人物默认拼音）；拼音排序且超过 50 项时右侧出现 A–Z 跳转条。拼音用浏览器的 `Intl.Collator("zh-u-co-pinyin")`，首字母用一组边界字（阿八嚓搭蛾发噶哈击喀垃妈拿哦啪期然撒塌挖昔压匝）比较得出，没有额外依赖。两层维度排序时先排父级，子级跟在父级下面。
- **范围页**：从目录树**拖动**节点（或 Ctrl/Shift 多选后拖）到这个列表，或节点右键「加入搜索范围」（加到最近用过的搜索页，没有就新开）；知识库根节点也可以拖。列表项的右键或 × 可移除，「清空范围」全部移除。拖动用指针事件实现（`scopeDrag.js`，不依赖 HTML5 拖放，因为 Tauri 窗口自己处理文件拖放可能吞掉它）。范围是各项的并集，只在有项的知识库里搜索；整个知识库作为一项（`whole`）时该库不限。
- 结果仍按知识库分组（顶部知识库标签带命中数），过滤只属于当前知识库，换库时清空。翻页有首页、上一页、页码输入、下一页、末页。
- 搜索页没有「随机一句」；它独立成了「每日一句」（见 9a 之后的说明：`app/src/lib/daily.svelte.js`）。
**节点属性**（`core/src/props.rs`，界面 `PropsDialog.svelte`，节点右键「属性…」）：搜索过滤里的部类、时域、人物、藏经、典类都可以由用户维护。外部知识库（CBETA、HTML、文件夹）内容不可编辑，但属性照样可改；属性窗口以后也是放节点其他功能的地方（现在含「别名」和「标签」）。别名（`props.db` 的 `node_alias`）：一个节点可有多个，不继承、不是分面，标题快搜按它匹配（和标题同等排序）。

- **存放**：单独的 `props.db`（与 `marks.db` 同目录），键是节点 `(知识库, 经号, 路径)`：CBETA 一部经是 `(库, T0262, "")`，HTML 文章和文件是路径，文件夹是相对路径，笔记是编号。**不写进数据源**。每项是「维度 → 值列表」，空列表表示「设为无」。CBETA 目录树里没有经号的文件夹节点（部类等）没有属性。
- **语义**：设了的维度**替换**数据本身给出的值（窗口里显示「默认」值，可「恢复默认」）；没设的维度保持数据的值；与默认值相同时不保存。**下传**：文件夹、笔记的属性适用于它下面的所有文件和子笔记，下层另有设置时以下层为准。部类、典类用 `/` 分两层（也接受 `：`、`>`）。窗口里输入时提示本库已有的值；时域和典类另有常用值（朝代名、经律论等）可以一点就加。
- **进索引**：建索引时把属性合并进每个文档的分面（`Overlay::apply`，`IndexDoc.keys` 是节点和它的上级）；保存属性后只对受影响的文档做**增量更新**（`search::update_docs`：按 `path` 删掉旧文档再写入新的，后台进行，完成后 `index-done` 提示）。没有索引时只保存，建立索引时生效。更新中重建索引或失败时可以重建索引。
- **导出导入**：数据包的每个节点带 `props`（该节点自己设的值），导入成为自建知识库时按新笔记编号恢复，所以属性不会丢。数据本身给出的默认值（如 CBETA 的作译者）不随包导出。删除自建知识库或笔记时，属性一起删除；解除外部知识库的绑定时属性保留，重新绑定后仍在。
- 命令行：`search <查询> --scope bulei/阿含部類`（可重复，同维度取「或」）；空查询列出全部。

分面按多个维度并列显示（部类、时域、人物、藏经、典类，见 8.4a），每个维度可以是层级的，父级计数等于各子级之和（旧界面中阿含部类 43 = 36 + 1 + 6）。每条结果显示标题、路径、贡献者，以及若干条带高亮的上下文片段，每条片段附「转到」入口。参考截图见 `docs/reference/`。

**8.5 定位**

引擎返回命中的文档和排序后，只对**当前页**的结果调用适配器的 `locate`，得到节点内所有命中位置。定位器格式由适配器定义（CBETA 是行号加行内位置，Markdown 是标题加字符偏移，PDF 是页码），核心只负责传递。旧实现用 Solr 高亮返回文本片段，点击后靠文字回找位置，重复句无法区分；新做法返回位置，每一处命中都有独立的行号。

**8.6 导出**

支持 Markdown、CSV、JSON。每条结果的引用文本由适配器的 `cite` 生成（例如「T08n0223，卷 1，0003b12」）。

**8.7 标题快搜（双击 Shift）**

独立于全文索引。启动时把节点标题、别名、作译者等载入内存，输入即响应，毫秒级。仓库过大时（如 Wikipedia 标题）改用磁盘上的 FST，通过内存映射访问。简繁不敏感，拼音首字母作为可选功能。

M2 的实现（`core/src/titles.rs`，命令行 `titles`，界面 `app/src/lib/QuickSearch.svelte`）：

- 条目（每个知识库一份，第一次用时建立，程序启动后在后台预先建立）：
  - CBETA：所绑定目录树里的每部经（按树的顺序；`T0220a` 这类大经的一段是单独的经条目，打开它自己的起点），接着是这部经 toc 的目次（序、品、分、经…，跳到锚点行）和卷（只有一卷的经不列卷）。toc 里指向不存在文件的目次不列。
  - HTML 知识库：每篇文章，所在文件夹作为上下文。
  - 一部经的经号、经名、作译者（或文章的文件夹）只存一份，供该经所有条目共用。本地文件夹库里的文件夹也是条目（`TitleKind::Folder`，标记「夹」），选中后在目录树中定位而不是打开阅读器。
- 匹配：查询按空格切成关键词，每个关键词都要出现在条目标题或它所属的经（经号、经名、作译者）、文件夹里。比较前用分词器的 `match_key` 折叠（NFKC、小写、繁转简，去掉标点和空白），所以简繁、全半角、标点都不敏感。
- 排序：标题以第一个关键词开头 > 关键词都在标题里 > 有关键词只出现在上下文；同一档内经和文章在前、目次其次、卷最后，再按标题与查询完全相同、标题短者在前；仍相同则保持目录树顺序。目次标题开头的序号（「1 序品」的「1」）不参与排序判断。
- 不分库（「全部」）时，各库的结果按上述排序合并，名次相同时按知识库的顺序；同时返回每个库的命中数。最多显示 200 条，另给总数。
- 实测 2025.Q1：部類目錄 317446 条，建立约 0.7 秒（release）；查询 4–8 ms。乾隆大藏经 8095 条、索达吉堪布全集 5242 条，各约 0.1 秒。
- **`#` 命令与 CBETA 引用**（`core/src/cite.rs`，CBETA 专用，沿用 cbeta-explorer 的做法）：查询以 `#` 开头时不搜标题，只按命令转到经、卷或行，结果是一条「转到 »」（不管选的是哪个知识库标签，定位用已绑定的 CBETA 知识库）。只输入 `#` 或格式不对时，弹窗列出格式说明。

  | 命令 | 转到 |
  | --- | --- |
  | `#T01n0001_p0001a01` | T0001（第 01 册）的 0001a01 行 |
  | `#T0001_p0001a01` | T0001 的 0001a01 行 |
  | `#T01, no. 1, p. 1a1` | T0001 的 0001a01 行（引用格式；也接受旧式 `p. 1, a1`、范围 `pp. 1a1-2b3` 取起点） |
  | `#T01n0001_1`、`#T01n0001_001` | T0001 的第 1 卷 |
  | `#T0001_1`、`#T0001_001` | T0001 的第 1 卷 |
  | `#T0001` | T0001（打开第一卷） |

  - 经号忽略前导零（`T1` 即 `T0001`，`JB480` 即 J 藏的 `B480`）；`T0220a` 这类目录里的分段在 catalog 里没有，去掉字母按 `T0220` 找。
  - 只给行时，卷是：起始行（`spine.txt`）不晚于该行的卷文件，而下一个卷文件的起始行晚于该行（或者页码重新开始，即进入下一册）；给了册号时只在这一册里找。
  - **粘贴引用**：粘贴 CBETA「复制为引用」的文字，如 `《坐禪三昧經》卷1：「第五法門……」(CBETA 2025.Q1, T15, no. 614, p. 269c29)`，输入框自动换成对应的命令 `#T15, no. 614, p. 269c29`，引文另外保留。不以 `#` 开头的查询里含有引用（`T15, no. 614, p. 269c29` 或行首 `T15n0614_p0269c29`）时，也在标题结果前面给出「转到 »」。`// Z 2B:8, p. 298` 这类其他版本对照不识别。
  - 引用行不一定是引文所在（上例写的是卷首 269c29，引文在 276a07）。有引文时，在这一卷里按精确短语找它（忽略标点、简繁折叠），找到就跳到不早于引用行的第一处（没有则第一处），打开时引文高亮。
  - 找不到经、卷或行时显示一条红色的提示。
- 界面：双击 Shift（两次之间没有别的键，400 ms 内）或顶部「快搜」按钮打开弹窗。上方标签是「全部」和各知识库（带命中数，Tab / Shift+Tab 切换，只能单选）；输入即搜；↑↓、PageUp/PageDown 选择，Enter 或单击打开（经打开第一卷，目次跳到对应行），Esc 或点外面关闭。每行左侧是类型（经、目、卷、文），然后是标题、所属经或文件夹、作译者，「全部」时右侧显示知识库。上次的查询和所选知识库保留到下次打开。

## 9. 内容展示与视图扩展

- 右侧只有**一个 Webview**，通过 Tauri 自定义协议（如 `smart-library://仓库/节点`）取内容，前端不直接访问文件系统。
- 适配器返回内容类型：HTML 片段、Markdown、原始文件（PDF、图片、音视频交给 Webview 原生处理）。
- 阅读选项（CBETA 的简繁切换、原书分行、注释显示方式）是 `content` 的参数，由适配器解释。
- 安全：来自 Wikipedia、Markdown 等的 HTML 一律消毒、禁止脚本，外部链接用系统浏览器打开。
- 命中高亮：前端拿到定位器后滚动并高亮，不依赖文字匹配。

**视图扩展：各数据源的专属功能**

专属的阅读功能不放进通用节点模型。适配器以可选扩展的方式提供，界面按能力声明决定显示哪些面板：

- **同级与上下级导航**：由目录树本身得出（`children`、`parent`），无需扩展。CBETA 的卷页因此自动获得同一部经的各卷列表。
- **节点内大纲（`outline`）**：返回节点内的标题层级，用于快速定位跳转。CBETA 是经内的品、章，Markdown 是标题，Wikipedia 是文章章节，PDF 是书签。这是通用扩展，多数仓库都能提供。
- **阅读选项（`view_options`）**：适配器声明可切换项，界面画成工具栏，选择结果作为参数传给 `content`。
- **专属渲染**：校勘注释等需要特殊交互的部分，由适配器在 HTML 中输出带语义的标记（如 `data-` 属性），再由随仓库类型加载的一小段前端脚本处理，不污染通用前端。

## 9a. 多标签阅读与知识库绑定

用户在 M1 之后提出，排在结构化阅读之后实现。两部分都已完成。

**多标签页**

- 阅读区支持多个标签页，一个文档只开一个标签页：再次打开同一文档时切到已有标签并跳到目标位置。
- 标签页可以**停靠**（左右、上下分栏，拖动标签到另一组）和**浮动**，用于多部经对照。
- 阅读进度要记录并还原：每个文档的当前卷、滚动位置（以屏幕顶部的行号 `lb` 记录，不用像素）、版式（段落、折行或折页）；程序重启后还原打开的标签页和布局。
- **用户已定：一卷一个标签；浮动既要窗口内浮动面板，也要独立系统窗口。**
- 实现（`app/src/lib/workspace.svelte.js`）：
  - dockview-core 8（MIT）。它的 ES 模块不带样式，样式从 UMD 版抽出放在 `app/src/vendor/dockview.css`，升级时要重新抽取。
  - 标签 id 就是卷路径。打开一卷时：已在独立窗口中就把那个窗口提到前面并跳转；已在标签中就激活并跳转；否则在当前组新开。卷选择和跨卷的目次跳转同样走这条规则（同一卷内的目次只滚动）。
  - 标签右键菜单：关闭、关闭其他标签、向右分栏、向下分栏、浮动（窗口内，默认占工作区约一半）、停靠回主区、在新窗口打开、查看原始（Raw）数据（独立窗口，见下）。也可以把标签拖到边缘停靠（拖动由 dockview 处理）。阅读区标题栏的定位按钮（图标和标题）上右键，弹出的是同一个菜单，位置在指针处（派发一个 `contextmenu` 给那个标签元素，不另做一套菜单）。
  - 搜索结果也是一个标签（`search`），可以和阅读标签并排；它不保存。
  - 独立窗口是 Tauri 的 `WebviewWindow`（标签名 `reader-<路径>`，URL 带 `?popout=` 参数），只显示一卷，标题栏有「停靠回主窗口」。它不写文件，用事件 `popout-progress`、`popout-closed`、`popout-dock`、`popout-open` 通知主窗口；主窗口用 `popout-jump` 让它跳转。用户关窗口才算关闭，程序退出时不算，所以重启后会重新打开。
  - 进度：每卷记录屏幕顶部的行号 `lb` 和版式（重启后从未显示过的标签，在第一次显示时才跳到记录的行，因为隐藏时无法排版定位）（滚动停止 0.4 秒后），最多 500 卷，关掉标签也保留，再打开同一卷时安静地回到原处（不闪烁标记）；搜索命中的跳转优先。
  - 保存：布局（`toJSON`）、独立窗口列表、进度、默认版式一起写进应用数据目录的 `workspace.json`（Tauri 命令 `load_workspace`、`save_workspace`，先写临时文件再改名），改动后 0.8 秒保存。启动时打开 bookcase 后还原。
  - 在程序里验证过：向右分栏对照两部经、同一卷再次打开只激活、浮动与停靠回主区、弹出窗口与停靠回主窗口、彻底重启后标签、滚动位置和弹出窗口都还原。
  - 切换标签时保留阅读位置：dockview 会把隐藏标签的元素移出页面，滚动位置随之归零；每个阅读标签记住自己的滚动位置，重新显示时放回（内容并不重新载入）。
  - 标签多于标签栏宽度时，dockview 把放不下的标签裁掉、列在下拉按钮里；激活其中任何一个（从目录树打开、Ctrl+Tab 或从下拉列表选）后，把标签栏滚动到当前标签处，保证它在可见范围内（`workspace.svelte.js` 的 `revealActiveTab`，在 `onDidActivePanelChange` 后按需要少量滚动）。
  - 在目录树中定位：标签右键「在目录树中定位」或阅读区标题栏的 ⌖ 按钮，展开目录树直到这部经（大经分段时取起点不晚于当前卷的那一段）或这篇文章，选中并滚动到可见处。目录树的展开状态因此由知识库面板统一保存（节点键是下标路径 `/0/3/5`）。
  - **视图导航**：激活过的阅读标签依次记入视图历史（每条带标题，最多 100 条，从中间导航后新建的分支截断），Ctrl/Cmd+Shift+← / → 或目录树工具栏右端的 ← / → 按钮回到上一个 / 下一个视图；目标标签已关闭时重新打开该文档，打不开的条目直接跳过并删掉。没有可导航的条目时按钮不可用（`ws.canBack` / `ws.canForward`）。历史与当前位置一起存进 `workspace.json`。
  - **视图历史对话框**（`ViewHistoryDialog.svelte`）：右键任一个视图导航箭头打开（比浏览器的历史菜单能容纳更多条目）。布局与「最近访问」相同：顶部一行是标题「视图历史」、筛选框和「清除记录」，下面是列表；最新在前，当前所在的那一行用列表共用的当前项样式（`app.css` 的 `.row-current`：accent-soft 底色加左侧 3px accent 竖条，不写「当前」字样）。可按标题、路径或知识库筛选；点一行直接跳到那个视图（不经过中间的条目），↑↓ / Enter 也能用；「清除记录」清空全部（之后箭头不可用，再切换文档时重新开始记）。不做「在新窗口打开」：视图历史属于主窗口，弹出窗口各自只有一卷；在新窗口打开还要处理标签唯一性和进度、最近打开的同步，收益不抵复杂度。
  - 标签右键菜单和标签栏右侧的「放不下的标签」下拉列表由 dockview 弹出，样式在 `app.css` 里统一改成本地右键菜单（`ContextMenu.svelte`）的样子（paper 底、细边框、圆角、阴影，选中行 accent-soft），因为它们在 `.sl-dock` 之外的 shell 里，不继承那里的主题变量。
  - 阅读区顶部只放工具（卷、目次、版式、编注方式、定位）；经名、经号、作译者和路径放在标签的悬停提示里（独立窗口放在标题栏文字的提示里）。标签的悬停提示最后一行是它所在的目录树路径（`ontreepath` 异步取得，取不到就没有），前面不加前缀。
  - 左侧目录区宽度可拖动分隔条调整（最小 180 像素，最大窗口的 70%，键盘左右键每次 20 像素，双击还原 300），保存在前端本地。

**知识库绑定**

- 绑定 bookcase 时解析 `menu_nav.xhtml`，列出其中的目录树让用户选择：
  - CBETA 自带的三棵树（簡易、進階、部類）**数据是同一份**，只能选一棵，默认 `bulei_nav.xhtml`。**绑定后不能更换**（2026-11 决定）：试用发现换树后，从搜索结果打开经文，目录树会变回原来的树；要换就先解除绑定再重新绑定。
  - 用户自加的树（如 `zhibei` 索达吉堪布全集、`longzang` 乾隆大藏经）数据各不相同，可以同时绑定，各自一个独立索引（规范第 7 节：每个仓库一个索引）。
- 判断两棵树是否「同一份数据」不写死文件名，而是看叶子指向：指向 `XML/` 的属于 CBETA 主数据，指向 `a/<库名>/` 的属于该库（`a/ZB/`、`a/LZ/`）；`help/` 等说明页不计。
- 依赖：自加树的内容是 `a/` 下的 HTML，需要先把它们接入为内容节点（抽取正文、建索引、阅读），见下面「HTML 文章」。

**知识库绑定的实现**

- core：`library.rs` 的 `classify_trees` 按叶子指向判断每棵树（`Cbeta`、`Html(代码)`、`Other`），实测 2025.Q1：簡易、進階、部類为 CBETA；`zhibei` 为 `a/ZB/`，`longzang` 为 `a/LZ/`。`HtmlTree` 从树里得到文章（含所在文件夹链和同级文章），并产生索引文档；`cbeta_docs` 产生 CBETA 的索引文档。`search::build_index` 只接收这些普通文档，适配器仍不依赖 Tantivy。
- 注册表：`<应用配置目录>/libraries.json`，每个知识库有 `id`（`cbeta`、`zb`、`lz`，重名加 `-2`）、`kind`（`cbeta` 或 `html`）、`title`、`source`（数据包路径）、`tree`。索引在 `<应用数据目录>/repos/<id>/index`。第一次启动时，旧版的单一 bookcase 设置自动迁移为 `cbeta`（部類），沿用原来的索引。
- 界面：左侧每个知识库是一个根节点，展开时才载入目录；「＋ 绑定」或在空白处右键「绑定知识库…」打开绑定对话框：选择文件或文件夹（系统对话框），读取后列出 CBETA 三棵树（单选，默认部類，已绑定的标「当前绑定」）和其他知识库（多选，已绑定的不可再选）。知识库右键菜单：展开、建立或重建索引、从同一数据包绑定其他知识库、解除绑定（系统确认框；删除该库的索引和标签，数据包不受影响）。根节点上显示「未建索引」「建索引 x%」「索引过期」「数据不可用」。
- 各知识库的索引可以同时建立，进度事件带库 id。
- 搜索：一次查询所有有索引的知识库，结果按知识库分组（规范 8.2）：顶部是各库命中数，默认显示第一个有命中的库，点选切换；分面、分页只针对当前库。标签 id 是 `<库>|<路径>`，工作区版本升到 2，旧版的阅读进度自动迁移到 `cbeta|…`，旧布局不再还原。
- 图片协议 `sl` 的地址带库 id：`http://sl.localhost/<库>/<数据包内路径>`，允许 `figures/` 和 `a/` 下的图片。

**知识库类型重构（2026-11 已定，分三步实施）**

知识库分外部（只读）和内部（读写）两类，都只作为目录树的一级节点出现：

- 外部：① CBETA 数据包（`bookcase.zip`，由菜单文件关联数据；菜单指向不同数据目录的可同时绑定，即现有实现）；② Wikipedia ZIM（只做标题与全文索引，不提供子级目录，适配器以后开发）；③ 本地文件夹（Link，默认只读，可设为读写，见 6.5；可链接多个；路径相同、或其上级目录已链接的不能再链接；可设置索引的后缀、文件大小等筛选；文档全文索引，媒体文件用媒体信息作正文）。
- 内部：自建知识库，可建多个一级目录，内容靠手动添加和编辑，先支持 Markdown，之后再考虑思维导图、白板；存储用 SQLite（见 6.4）。
- 添加入口：目录树右键菜单（含空白处），以及目录树旁的「＋」菜单（「文件」仅内部库可用；「知识库…」打开向导：先选类型，再填各类型的参数）。
- 步骤：1 注册表、向导、菜单（已完成：向导第一步选类型，ZIM、文件夹、自建先占位；＋菜单；CBETA 目录树绑定后固定）；2 外部文件夹（已完成，见下）；3 内部库（已完成，见下）。

**外部文件夹实现（`core/src/folder.rs`，第 2 步）**

- 注册表项 `kind: "folder"`，`source` 是规范化后的绝对路径，另有 `exts`（索引的后缀）和 `max_mb`（单文件上限，0 为不限）；默认后缀 `txt md html htm`，上限 50 MB。
- 链接冲突（`folder::conflict`，比较规范化路径，不分大小写）：同一文件夹、上级已链接、里面已有链接的文件夹，三种都拒绝。
- 目录树按需展开：每次只列一层（先文件夹后文件，跳过 `.` 开头的项和不符合筛选的文件）；节点带 `rel`（相对根的路径）和 `lazy`。不跟随符号链接。
- 文本类后缀（txt、md、html、xml、csv、json、srt 等）读全文，一行一段，与 HTML 文章同一套阅读、定位、高亮；`pdf`、`docx`、`pptx`、`odt` 也读全文（`core/src/doctext.rs`：zip 里的 XML 取文字，PDF 用 pdf-extract，部首字形用 NFKC 还原；旧 `.doc` 和扫描的 PDF 没有文字，读不出时显示媒体信息）；其他后缀用「媒体信息」（文件名、所在文件夹、类型、大小、修改日期）作正文。媒体标签（ID3、EXIF、时长）暂不做。
- 索引文档：`path` 为相对路径，分面 `/bulei/` 取前两层文件夹，`/book/` 取所在文件夹，`/kind/` 取后缀。数据版本是「文件数 + 路径、大小、修改时间的哈希」，只在建索引时算，所以不显示「索引过期」，文件夹有变化要手动「重建索引」。
- 标题快搜：每个文件一条，所在文件夹作上下文。图片不提供。`.md` 用 `markdown.rs` 的简化 Markdown 渲染（和内部库相同）。

**内部库实现（`core/src/notes.rs`、`markdown.rs`，第 3 步）**

- 注册表项 `kind: "notes"`，没有 `source`；数据在 `<应用数据目录>/repos/<id>/notes.db`（SQLite，`rusqlite` 的 bundled 版，已验证能在 gnu 工具链上编译）。**一个内部库一个数据库**，所以可以建多个互不相干的知识库；知识库就是目录树的一级节点，它的顶层笔记是它的子级。
- 表 `notes(id, parent_id, title, content, content_type, position, created, updated)`，`parent_id` 级联删除；`NotesStore` 提供 `children / get / create / update / delete / move_to / rows / fingerprint`。节点不分文件夹和文件：每个节点都有标题、可以为空的 Markdown 内容、可以有子级。移动时检查不能放进自己的子孙里。
- 阅读：`markdown::to_html` 把 Markdown 子集（# 标题、段落、- 和 1. 列表、> 引用、代码块、`**粗**`、`*斜*`）转成文章白名单 HTML，再走 `read_article`，所以定位、高亮、目次、搜索片段都和 HTML 文章一样。
- 编辑：阅读标签里点「编辑」，换成文本框（Ctrl+S 保存，Esc 取消），保存后重新载入；新建的空笔记直接进入编辑。目录树右键：新建子笔记、重命名、上移、下移、删除（带下面的子笔记，系统确认框）；知识库右键：新建笔记。「＋」→「文件（笔记）」把笔记建在最近点开的笔记下面，没有就建在第一个内部库的顶层。
- 索引：以 SQLite 为准，索引手动「重建」；数据版本是「笔记数、最近修改时间、内容总长」，改动后根节点显示「索引过期」。标题快搜每次写入后失效重建。
- **回收站（2026-11）**：删除内部笔记（连同下面的子笔记）前，先把整棵子树做成一个 `kind = "deleted"` 的快照（`snapshots.db`）：内容是 JSON（`notes::DeletedTree`，每个节点带原来的 id、标题、内容、类型、位置和子节点），另记**标题路径**（`path`：从顶层到直接上级的标题，用 `NotesStore::folders_of` 取，不记 id）。快照对话框与按文档的 `list` 不显示这种快照，只有知识库右键「回收站…」（`NotesTrashDialog.svelte`）列出。恢复时按标题路径重建：某一级标题在现在的树里存在就重用，不存在就新建一个同名的空笔记；然后在最终上级下新建这一篇。只有恢复的这一篇本身遇到同名时才用「标题 2」「标题 3」，它下面的子节点按原样新建。回收站里的其他条目不受影响——只恢复 Chapter1 不会动 Book 的条目，也不会恢复 Note1。`NotesStore::restore_deleted` 在一个事务里建回；每个节点原 id 空闲就沿用（日记的固定日期 id 和按 id 记的书签能重新对上），被占用就换新 id。旧版快照没有标题路径时按原来的 id 兜底（`relocated`）。删除时把子树里引用的图片记进 `notes.db` 的 `trash_refs`，每日图片清理跳过这些名字；恢复或永久删除快照时释放保留。快照里还按旧 id 记下每个节点的属性、标签和别名（`DeletedMeta`）；`restore_deleted` 返回旧 id 到新 id 的对应，命令据此把 `props.db` 的维度和别名、`marks.db` 的节点标签写回（属性被显式设为空的维度也保留）。删除时再把这些节点的属性从 `props.db` 移除，节点标签记录也从 `marks.db` 去掉（快照里已经保存）。恢复成功后删除这个快照，恢复出的笔记记入「待索引」。旧版快照没有 `meta`，不能恢复属性。目录树里恢复出来的节点默认折叠（`showNew` 清掉该索引路径及其子路径的展开状态），以免沿用旧节点的展开状态出现「展开但子节点没加载」。
- **删除知识库会永久删除 notes.db**（用户自己写的数据，没有源可以重导入），同时删除该库的删除快照；确认框单独写明。备份目前靠手动复制 `repos/<id>/notes.db`。
- 界面（2026-11）：去掉顶部工具栏。目录树工具栏左边是「＋」、标题快搜（纸飞机，双击 Shift 或 Ctrl/Cmd+G）、全文搜索（放大镜，Ctrl/Cmd+H，弹出输入框，回车搜索后结果在标签里）、查词典、收藏与标签、最近访问（以及 AI 助手开关），右边是两个视图导航箭头（← →，同 Ctrl/Cmd+Shift+←/→；没有可导航的视图时按钮不可用）；没有单独的「知识库」标题。目录树下方一行的左边是公用的状态位（`app/src/lib/status.svelte.js`：任务按 key 登记一行短文字，`status.set(key, text)` 显示、`status.clear(key)` 撤掉，多项同时存在时用全角空格连起来；建索引进度就显示在这里，没有任务时显示灰色的「知识库」），右边是设置、消息、关于三个图标按钮（消息图标带条数）。消息列表在目录树左下方弹出。
- 版本号用 `YY.MM.DD`（如 26.11.08）。Cargo 和 Tauri 要求 semver，所以文件里写 `26.11.8`（不补零），界面显示时补零（`app_info`）。每次 `npm run tauri build` 前由 `tools/stamp-version.cjs` 按当天本地日期写入五处（`core`、`cli`、`app/src-tauri` 的 Cargo.toml、`tauri.conf.json`、`app/package.json`），并同步 `Cargo.lock`、`app/package-lock.json`。GitHub Actions 的正式包不盖章，沿用标签里的版本，所以发版当天先提交盖章后的版本文件，再打同日期的标签。窗口标题：`文档标题 by 作译者 - 『知识库』 - Smart Library 版本`，没有打开文档时只有程序名和版本。
- 当前文档的快捷键（`shortcuts.js`，弹出窗口里也有效）：Ctrl+T 标签、Ctrl+D 书签（当前读到的行）、Ctrl+P 属性、Ctrl+L 在目录树中定位、Ctrl+N 新建笔记、Ctrl+W 关闭标签、Ctrl+Tab / Ctrl+Shift+Tab 切换标签、Ctrl+Shift+S 简体 / 原文；白板和脑图里不拦截这几个键（它们有自己的用法）。
- 快捷键在阅读器里选中文字时：Ctrl/Cmd+G 或双击 Shift 以选中文字开始标题快搜，Ctrl/Cmd+H 直接以选中文字全文检索（没有选中文字时打开输入框）；Ctrl/Cmd+K 查词典（有选中文字时直接查这个词，没有时打开词典窗口）。弹出的阅读器窗口里同样有效，由主窗口执行。
- 提示消息：以浮层显示（不挤动布局），5 秒（错误 10 秒）后自动隐藏；鼠标停在上面或期间没有任何操作则不隐藏；顶部「消息」按钮可回看本次运行的全部消息。
- 最近打开、收藏、书签、阅读进度都已实现（见各节）。
- 还没做：拖放移动（后端 `move_to` 已有）、笔记的创建与修改时间显示、附件和图片、思维导图与白板、写入后的增量索引。

**添加笔记与最近打开（2026-11）**

- 添加笔记对话框（`NoteDialog.svelte`）：「位置」是 `知识库/文件夹/…` 的路径，输入时从所有自建库的现有节点里提示；第一段若是自建库名就指定该库，否则用默认库（右键或最近选中的所在库，再不然第一个自建库）。路径里不存在的层级在点「创建」时一起建好（`NotesStore::ensure_path`）。外部库不出现在提示里，也不能添加。

**从目录树的节点搜索（2026-11）**

- 目录树右键菜单（知识库根和各节点）有「从这里搜索标题…」「从这里搜索全文…」，范围是这个节点和它下面的全部内容；目录树不支持多选，一个节点就是一个范围。
- 实现：`SearchRequest.within`（`Within { books, paths }`，用 `TermSetQuery` 限定 `book` 或 `path` 字段，核心有测试）。CBETA 取节点下的经号，HTML 库取文章路径（前端手里有整棵树）；文件夹库和自建库的树是按需加载的，前端只传 `rel`（文件夹路径或笔记编号），由后端展开成文件或笔记（`resolve_within`）。整个知识库的根只限定知识库。
- 标题快搜用同一个范围对象过滤条目（经号或路径在集合里）；全文搜索的结果页在分面上方显示「范围：知识库 › 节点」，可清除。弹出的搜索框里也有范围标签，可取消。

**设置（2026-11）**

- 目录树下方的设置图标或 Ctrl/Cmd+,：主题（跟随系统、浅色、深色，深色靠 `<html data-theme>`）、界面缩放（80–300%，用 WebView 的缩放）、界面字体、阅读器字体、字号基准（14–72 px，正文和其它元素都按 em 跟它缩放）、字重（标准、稍粗、加粗）、字间距（0–0.3 em，默认 0.04）、行间距（1.4–2.6）、段间距（0–2 em，默认 0.35）、版心宽度（20–100 em，默认 46；可勾选「全宽」按可视区宽度自适应）、选字查词（按住 Ctrl/Cmd 选字、选中即查、关闭，默认按住 Ctrl/Cmd）。不做复杂的主题机制，只有明暗两套颜色变量。字体下拉列表由后端读本机字体文件（`fonts.rs`，ttf-parser + memmap2，只读 name 表，每次运行算一次）：有中文名的在前面，显示中文名；值为 `sys:<英文族名>`，也可以手动输入字体名。
- 字体默认按平台取系统自带的（2026-11）：界面字体默认是系统界面无衬线（`--font-ui`：Segoe UI + 微软雅黑、系统 UI 字体 + 苹方、Noto Sans CJK），阅读器字体默认是系统中文衬线（`--font-serif`：先排 Iowan Old Style / Palatino / Georgia 等拉丁衬线，再排 Songti、Noto Serif TC、細明體、宋体），所以西文用衬线的书页感、汉字用系统宋体，小字号界面文字不会落进宋体的点阵字形。`settings.svelte.js` 里界面与阅读器各有一张字体预设表（`UI_FONTS` / `READER_FONTS`），「系统默认」一项的值为空，只是为了不写内联变量、让 CSS 里的默认栈生效；界面另留「宋体 / 明体」一项给喜欢通篇宋体的人。阅读器、笔记、词典和设置里的示例文字用 `var(--reader-font, var(--font-serif))`，不再继承界面字体。
- 选字查词（2026-11）：只在只读阅读器（`Reader.svelte`，含弹出的阅读窗口）里生效，笔记、脑图、白板不参与，因为编辑时选字是常态。「按住 Ctrl / Cmd 选字」在按住修饰键选中文字并松开鼠标时查词，普通选字与复制不受影响；「选中即查」每次选中都查，按住 Ctrl / Cmd 时不查（这时通常是复制）；「关闭」不查。只在左键选择后、且选择内容与按下鼠标时不同才触发（单纯点击、Ctrl/Cmd+点击不查）。选中的文字去掉多余空白后超过 10 个字、或含 Unicode 标点 / 符号（`\p{P}`、`\p{S}`，如句读、括号、下划线，行号里带 `_` 也会被挡下）时不查。查词用 `openDictWindow(词, { reuse: true })`：第一次打开标题为 `dict-select` 的词典窗口，之后每次通过 `dict-query` 事件送进同一个窗口，不会每选一个词就多开一个窗口；Ctrl+K 的「查词典」仍是每次都开新窗口。
- 字重是三个档位而不是滑杆：CSS 没有相对字重（`font-weight` 不能像 rem 那样按基数放大），中文字体也大多只有两三个真实字面，连续数值会被吸附到同一档。`settings.svelte.js` 的 `WEIGHTS` 表给出每档的正文和强调字重，以及正文 / 强调的描边宽度（`-webkit-text-stroke-width`，用 em，字体没有对应字面时靠它保证档位有效）。正文用 `--reader-weight`，强调用 `--reader-strong-weight`；`b`、`strong`、`.head`、`.juan`、CBETA 粗体读法都用强调档，覆盖浏览器的 `bolder`（它按固定阶梯走，600 以上饱和，基准提高后强调会和正文一样粗）。加粗档的强调另加 0.024em 描边，否则两字面字体到顶后强调无法区分。只作用于阅读器和词典详情，笔记编辑器不跟随。
- 保存在 WebView 的 localStorage（便携模式下就在 `data/webview/` 里），`settings.svelte.js` 把它写成 CSS 变量（`--ui-font`、`--reader-font`、`--reader-size`、`--reader-line`、`--reader-spacing`、`--reader-para`、`--reader-max-width`、`--reader-weight`、`--reader-strong-weight`、`--reader-stroke`、`--reader-strong-stroke`）；弹出的阅读窗口同源，改动通过 `storage` 事件同步。

**查词典与词典导入（2026-11）**

- 词典窗口（`core/src/dict.rs`、`DictWindow.svelte`、`DictReaderView.svelte`）读 `.words`：文件头（版本 3、字符集、压缩方式、元数据、条目数、内容分区表），标题区按记录顺序存放（`entry_size i16`、`pid i32`、`type u8`、`content_mark i64`、`title_len i16`、标题字节），词义区按 `content_mark` 存 `i32` 长度加压缩字节；标题区用 mmap 扫描，多个标题可以指向同一份词义。读词典不建索引，搜索是标题区线性扫描（前缀 / 包含 / 后缀 / 精确由查询语法决定）。左侧词条列表里右侧正在显示的那一条用共用的当前项样式（`.row-current`，与视图历史、AI 会话列表、目录树选中节点相同）。
- 配置在 `<配置目录>/dicts.json`：`paths`（`.words` 文件或目录，目录递归扫描）和 `disabled`（停用的词典 id）。设置 → 词典里添加、启用、排序过滤。词典 id 由名称和文件大小算出。
- **导入**（`core/src/dict_import.rs`、`core/src/dict_build.rs`）：设置 → 词典的「导入第三方词典…」/「导入文件夹…」选择文件；支持的来源转换成 `.words` 放在 `<数据目录>/dicts/`（自动加入 `paths`），同名再导入时覆盖。源文件不动，转换结果可以删除后重新生成。
  - **TXT**：按旧 Java `DictFileTxt` 的规则，一行 `【词条】词义`，`\\n`（两个反斜杠加 n）表示换行；没有 `】` 的行忽略。文件按 BOM 判断 UTF-8 / UTF-16；无 BOM 且不是合法 UTF-8 时按 GB18030 读。文件名是词典名。
  - **StarDict**：同名 `.ifo` + `.idx`（或 `.idx.gz`）+ `.dict`（或 `.dict.dz`，dictzip 是 gzip 兼容的，整个解压）；`bookname` 作词典名，`sametypesequence` 有则按类型序列读，没有则按 `type + 数据` 逐段读；默认 32 位偏移，`idxoffsetbits=64` 时用 64 位。文本类型（`m l h x t y k w n r`）转正文，`x` 去标签，`g`/`P` 图片写入 `.words_extra` 并在正文里写 `<PIC>名</PIC>`。
  - **MDict**：`.mdx`（可选同名 `.mdd` 资源）。支持引擎版本 1 和 2、zlib 压缩、UTF-8/GBK/GB18030/UTF-16；`Encrypted="2"`（键块信息加密）用旧 Java 的 RIPEMD-128 + `_fast_decrypt`（先按 `key = ripemd128(块[4..8] + 0x3695)` 派生，再逐字节交换半字节、异或前一个密文字节、序号和密钥）解开；`@@@LINK=词条` 重定向在导入时解析（最多 8 跳）。`Encrypted="1"`（词条块加密）和 LZO 压缩暂不支持，会给出原因。
  - **MDD**：键块信息的编码可能和头部 `Encoding` 不一致（常见是头部留空但内容为 UTF-16LE），解析时按“能否正好消费完整块”在 1/2 字节宽度之间切换；正文里 `<img src="…">` 能对上 MDD 资源时改成 `<PIC>归一化路径</PIC>`，只把被引用的资源写进 `<词典名>.words_extra`（ZIP；已经是压缩格式的图片用 stored，不再压）。读词条时 `<PIC>` 以 data URI 放进详情 HTML；后端和前端的消毒都只放行 png / jpeg / gif / bmp 的 data URI（不放 SVG），并允许 `img` 的 `alt`、`width`、`height`。
  - **变体与去重**：每条词条额外生成小写、简体、繁体三种写法，已经存在的写法不重复添加（小写比较用折叠形式，避免大小写只差一个的重复条目）。简体用 `data/t2s.txt` 和 `data/variants.txt`（`analyzer::to_simplified`）；繁体用同一张表的反查（`analyzer::to_traditional`），优先标准字形（说 → 說，不是 説），后/干/台/只/系/余/谷/斗/松/胡/云/里/面/佛 这类一字多形的字保持原样，不做猜测。词义按 128 位指纹去重，多个词条共享同一份压缩词义；标题顺序沿用来源顺序，变体追加在最后。
  - 已知限制：繁体是逐字近似，不是旧 Java 的词语级转换；MDD 只带 `<img>` 引用的资源；不支持 LZO 和加密词条块；TXT 只认 `【】` 格式。
- 命令行（先跑通再进界面）：`smart-library dict import <文件或目录…> [--out DIR]`（默认 `app_data/dicts`）、`dict list`、`dict search <词> <词典…>`、`dict lookup <词> <词典…>`。样例在 `samples/dict/`（TXT、StarDict、带加密键块信息和 MDD 的 MDX），由 `tools/make_dict_samples.py` 生成。

**阅读器选中文字菜单、打开过标记、收藏与标签（2026-11）**

- 阅读器右键菜单（选中文字时）：复制文字；复制文字（&引用出处）（CBETA 用 `(CBETA 2025.Q1, T15, no. 614, p. 269c29)`，其他库用 `—— 《标题》 · 知识库 · ¶n`，后端 `cite_text`）；全文检索、精确检索、快捷检索（标题快搜带入文字）、页内查找（命令 `find_in_page` 用 SendInput 按下 Ctrl+F，打开浏览器自带的查找栏，选中的文字自动填入；先用 `window.find` 保证选区就是这段文字；非 Windows 退回 `window.find`）、检索本书（`within` 限定本书或本篇）；查拼音（弹窗逐字显示，拼音用 `<ruby>` 排在字的上方；底部按钮分别复制纯拼音和「汉字(拼音)」组合，后端 `pinyin::convert` 一次给出逐字对和两种文本）、词条、词义先占位（需要额外的库）；添加书签、添加收藏。没有选中文字时只有「添加书签」。独立弹出窗口里菜单相同，窗口之间用 Tauri 事件通信（`popout-action`、`popout-shortcut`），搜索、书签、标签由主窗口执行并取得焦点。
- 目录树的绿色表示「曾经打开过」（不是读完，也不是当前）：依据历史记录（`History::opened`），节点按经号（CBETA）或路径匹配；当前选中的节点是加粗的强调色。
- **标记（mark）统一模型**（`core/src/marks.rs`，`<数据目录>/marks.db`）：书签（位置加那一行的文字）、收藏（选中的文字、位置、备注）和节点标签是同一种记录，都可以有标签。「对选中文字打标签」就是添加收藏时填标签，所以不另设功能；它同时起锚点的作用（`lb` 加原文，打开时高亮原文）。记录保存来源（知识库名、文档标题、作者），知识库解除绑定后仍能浏览，只是不能跳转。
- 节点标签（kind `node`）：CBETA 目录树上的节点是整部经（`book_id`，`path` 为空）；阅读器工具栏的标签按钮标的是当前这一卷（`path` 是卷路径）；其他库按文章、文件或笔记的路径，两处入口对它们指向同一个节点。节点标签为空就删除该记录。
- 界面：工具栏的书签图标或 Ctrl/Cmd+B 打开「收藏与标签」：左边是全部标签（点一个标签列出所有带它的记录，不是输入式搜索），右边是记录（类型、文档、来源、文字、备注、标签），可按类型、当前文档、文字筛选，点击回到原处，可编辑备注和标签、删除。

**HTML 文章（`core/src/article.rs`）**

- 两种格式：`a/LZ/` 是 Trilium 导出（正文在 `div.ck-content`，标题在 `h1[data-trilium-h1]` 重复一次，跳过）；`a/ZB/` 有 `<meta author= library= catalog= period= book= name=>`，正文是带 id 的 `p`，部分文章有同目录下的配图（`src="a/69.jpg"`，相对文章所在目录）。
- 文章读成与卷相同的 `VolumeText`，**以段落代替行**：每个块（p、h1–h6、li、td 等）开始一个「行」，编号 `¶1`、`¶2`…；段落之间在 `text` 里加一个不计数的空格。因此定位、片段、高亮、跳转都直接复用；命中位置显示为「¶13 第1字」。
- HTML 只按白名单重建（段落、标题、列表、表格、粗体斜体、上下标、图片），脚本、样式、链接、事件都不会进入阅读区；图片路径不能跳出数据包。
- 索引文档的分面：`/bulei/` 取目录树里前两层文件夹，`/book/` 取 meta 的 book（没有则取所在文件夹），`/kind/` 取 meta 的 catalog，`/period/`、`/person/` 取 meta。
- 实测：乾隆大藏经 8095 篇，建索引约 6 秒（release）、158 MB；索达吉堪布全集 5242 篇，约 8 秒、102 MB。

**每日一句**（`lib/daily.svelte.js`，后端命令 `random_sentence`）：程序常开不重启，所以不在启动时弹，而是定时检查（启动 15 秒后一次，之后每 30 分钟）：今天还没有句子、且有知识库建好索引时，从「来源」里随机取一卷再取一句（以。？！；结尾、8–60 字、汉字占七成以上，按各库文档数加权），记在本机存储里（重启后保留）。目录树下方的喇叭按钮上显示 1，点开后句子像提示一样弹出约 12 秒（鼠标停在上面不关），角标去掉；之后再点仍可看今天这句。弹窗里有「打开原文」（跳到该行并高亮）和「换一句」。设置里可以关闭功能、查看和移除来源；来源在目录树右键「加入每日一句来源」添加（知识库、节点、多选都可以），没有来源就用全部已建索引的知识库。

## 10. 数据与目录布局

**便携模式（2026-11 已定）**：数据放在程序旁边的 `data/` 文件夹里（`data/config/libraries.json`、`data/workspace.json`、`data/repos/…`、WebView2 的配置 `data/webview/`），整个文件夹可复制或带走。发布版总是用这个位置；开发版默认仍用系统的应用目录，在可执行文件旁手动建一个 `data` 文件夹即可改用便携位置。旧位置的数据不会自动迁移（索引可重建，笔记库 `notes.db` 需手动复制到新位置的 `repos/<id>/`）。

```
app_data/
  config.toml                 全局设置
  registry.db                 仓库注册、目录树设置、阅读历史、书签、收藏
  repos/<repo_id>/index/      该仓库的 Tantivy 索引（可删可重建）
  repos/<repo_id>/notes.db    仅自维护仓库：用户数据
```

原则：只读仓库只记录路径或引用，不复制、不修改源数据；所有衍生数据（索引）都可以随时删除重建；用户自己创作的数据（笔记）单独存放，便于备份与迁移。

每个阶段都应该是可独立使用的软件，避免走到后期才发现架构问题。

## 附录 A：CBETA bookcase 格式

来自实际样本（`samples/cbeta`）和对旧 Java 实现（cbeta-explorer 作者的 appxi-cbeta 库）的阅读。这些是靠样本很难发现的隐藏规则，新实现应逐条对照。

### A.1 读取与入口

- zip 根目录为 `Bookcase/CBETA/`，`index.xml` 等都在这一层；导航里的 `XML/T/T01/…` 是相对这一层的路径。
- zip 条目名：实测 2025.Q1 包的 85159 个条目**都没有 UTF-8 标志**；CBETA 自己的条目是 ASCII，用户加入的 `a/` 目录下 8773 个条目名是 **GBK**。新实现逐个条目读原始字节：是合法 UTF-8 就按 UTF-8，否则按 GBK（`source::decode_entry_name`）。不能用 zip 库默认的 CP437 解码。
- 压缩方式只有 deflate（8）和 stored（0），`zip` crate 只开 `deflate` 特性即可（默认特性带的 lzma 等 C 代码在 Windows GNU 工具链上编译失败）。
- 必须存在且不为空的 7 个文件：`advance_nav.xhtml`、`bookdata.txt`、`bulei_nav.xhtml`、`catalog.txt`、`menu_nav.xhtml`、`simple_nav.xhtml`、`spine.txt`，缺任一个就认为不是有效的 bookcase。
- 也支持已解压的目录，依次尝试根目录、`CBETA`、`Bookcase/CBETA`、`cbeta/Bookcase/CBETA` 下的 `index.xml`。
- **编码**：`catalog.txt` 是 UTF-8，`bookdata.txt` 是 UTF-16LE（带 BOM）。统一按 BOM 自动判断编码最稳妥。
- `index.xml`：指向 `catalog.txt`、`bookdata.txt`、`spine.txt`、`menu_nav.xhtml`，并带有版本号和日期。旧实现把日期折算成季度版本（1、2 月算上一年 Q4，3–5 月为 Q1，6–8 月为 Q2，9–11 月为 Q3，12 月为 Q4）用于缓存失效。
- `spine.txt`：列出所有卷文件及各卷起始行号（形如 `XML/T/T01/T01n0001_001.xml , 0001a01`），旧实现没有使用它，可用于校验。

### A.2 书目文件

- `catalog.txt` 每行按「, 」切成 8 段并去掉空白：藏经代码、部类、子类、册号、经号、卷数、经名、作译者。部类和子类拼成「部类/子类」（子类常为空）。作译者带朝代前缀，如「唐 慧菀述」。
- 经 ID 是藏经代码加经号，如 `T0004`、`A1267`。
- 经名可能带「(第N卷-第M卷)」后缀：解析出卷范围，并从经名中去掉。同一经 ID 出现多行时合并成一部经，每行把自己的卷范围映射到本行的册号（得到「卷号到册号」的表）。**卷范围只是提示，不是保证**：A1493 的名称写「第3卷-第12卷」（10 卷），但卷数栏是 9。以 toc 和文件实际存在为准。
- 卷文件路径可以直接构造：`XML/{藏经}/{藏经}{册}/{藏经}{册}n{经号}_{卷号，三位补零}.xml`。
- `bookdata.txt` 按「,」切成 5 段：藏经代码、数字、简称、全称、英文名。数字的含义未知，暂不使用。

### A.3 目录树

- `menu_nav.xhtml` 列出目录树。CBETA 官方是三棵：`simple_nav`（簡易）、`advance_nav`（進階）、`bulei_nav`（部類）。树 ID 取文件名去掉 `_nav.xhtml`。
- 用户的 bookcase 另加了两棵：`zhibei_nav`（索达吉堪布全集，5242 个叶子）和 `longzang_nav`（乾隆大藏经，8095 个链接节点），所有叶子都指向 `a/` 下的 HTML 文件（全部存在）。所以树的数量不固定，按 menu 列出的为准。
- `nav` 的 `default` 属性是**默认树的 ID**：`default="zhibei"` 即 `zhibei_nav.xhtml`。
- 所有 `*_nav.xhtml` 的顶层第一项都没有 `<li>` 包装。解析时把 `nav` 元素本身连同它的直接子 `li` 当作第一层即可自然解决。每个 `li` 先找 `span`（目录节点，子级在 `ol > li` 里），没有则找带 `href` 的子元素（叶子）。
- 叶子的链接直接指向卷文件（`XML/T/T01/T01n0004_001.xml`），文字形如「T0004 七佛父母姓字經」，**只指向该经的第 1 卷**。叶子按 `href` 的前缀分四种处理：
  - `XML/…`：取文字的第一个词（空格或全角空格之前，如 `T0004`）查 catalog。查不到且以小写字母结尾（如 `T0220a`）时，去掉字母查基础经，克隆一份，标题取整段文字，起点记为该链接。也就是说，nav 里的一个叶子可能只是某部大经的一段。
  - `toc/…`：用属性 `i` 作为经 ID，到 catalog 里查。
  - `a/…`：扩展库条目，元素是 `<a>`，属性 `i` 是 ID（如 `ZBzz005_001`、`LZa_1`），`a` 是作译者、`p` 是朝代（均逗号分隔，可缺），库名取路径第二段（`ZB`、`LZ`）。目标是 Trilium 导出的 HTML（正文在 `div.ck-content`，标题在 `<title data-trilium-title>`），同目录下有配图 `.jpg`（共 7226 张）。这类叶子没有 catalog 记录，M0a 只报告不解析；之后作为「HTML 文章」内容节点处理（每个文件一个节点，参与全文索引）。
  - `help/other/…` 及其他：以属性 `i` 或链接的哈希为 ID。实测 simple、advance、bulei 三棵树各有 303 个，都在「漢譯南傳大藏經」下，是 N 藏的说明、序和各册目录页（`.htm`），不对应经。
- 无链接的 `span` 节点：标题取属性 `t`，没有则清理文字。文件夹标题带机器码，如「01 阿含部類 T01-02,25,33 etc.」，清理规则：按空格切词，去掉以字母或等号开头的词、开头为数字的词，「etc.」按空白处理，以「／」分组。
- nav 的 `han-lang` 属性标明文字类型，默认繁体；用户加的两棵树是 `han-lang="hans"`（简体）。这意味着标题快搜和全文搜索都要考虑繁简互查。
- 用户加的两棵树里，顶层第一项**有** `<li>` 包装，与 CBETA 的不同；现有解析两种都能处理。
- **链接节点也可以有子级**：`longzang` 里有 `<li><a href="…/菩萨戒本.html">菩萨戒本</a><ol>…</ol></li>`（2 处，共 5 个子项），即「有内容且有子级」的节点。解析时带链接的 `li` 也要读它的 `ol`。样本 `samples/cbeta/longzang_nav_fragment.xhtml`。
- 实测（2025.Q1）：simple、advance 各 6137 个叶子，5834 个对应到经；bulei 5449 个叶子，5146 个对应到经，其中 15 个是大经的一段（克隆）。

### A.4 每部经的 toc 文件（经与卷的关联）

- 经的 toc 路径由 catalog 的经 ID 推出：`toc/{藏经代码}/{经ID}.xml`（如 `toc/T/T0004.xml`），位于 `Bookcase/CBETA/` 下。
- 里面有两个 nav：`nav type="juan"` 一定有，列出每卷的文件和起始锚点；`nav type="catalog"`（经内章节目录，嵌套的 `ol/li`）可有可无，T0004 就没有。
- 一部经的所有卷文件，等于这两个 nav 里全部链接去掉 `#` 之后的文件路径，去重并排序。
- **一卷可能分在两册**：同一卷号对应两个文件，如 `L130n1557_017` 和 `L131n1557_017`、`X39n0714_003` 和 `X40n0714_003`、`GA036n0037_002` 和 `GA037n0037_002`。catalog 里两行的卷范围在这一卷重叠（`(第1卷-第17卷)`、`(第17卷-第34卷)`），toc 两个文件都列。所以「卷号到册号」是一对多，卷文件要按（卷号，路径）去重，不能只按卷号。每个文件仍是一个文档。样本 `samples/cbeta/toc_X0714.xml`。
- toc 的 `juan` 列表不一定一卷一条：X0714 每卷分成「一上之一」「一上之二」等多条，指向同一文件的不同锚点。
- 实测（2025.Q1，4798 部经）：每部经都有 toc 文件，都至少有一个卷文件，toc 列出的卷文件全部存在。卷号可以有缺（A1267 没有卷十一，toc 也不列）。
- 锚点是 `p` 加行标记（`p0001c18` 即第 1 页 c 栏第 18 行），与卷 XML 里的 `lb n` 一致，可直接作为「转到」的定位。
- **章节目录里的顺序有语义，不能按锚点排序**：T0262 的「附文」锚点在第 198 页，却排在第 55 页与第 56 页的章节之间。章节可以嵌套（附文下有子项），也可以平铺；条目文字自带序号，如「1 序品」。
- 卷标题在 toc 里是「第一」「第二」，界面显示用「卷一」。
- 补缺：卷号不从 001 开始，或相邻两个卷号相差大于 1 时，旧实现补出缺的卷节点（类型为 title，即没有内容的占位），之后再用 catalog 的「卷号到册号」表补一遍。这些占位卷的文件可能并不存在，新实现用 zip 目录判断。
- 章节节点：当父节点还没有子节点、且与第一个子节点指向同一个文件时，子节点继承父节点的锚点。

- **不被任何经引用的卷文件**（实测 587 个）全部属于两套 catalog、bookdata、nav 里都没有登记的藏经：`LC`（呂澂佛學著作集，8 部 127 卷）和 `Y`（印順法師佛學著作集，44 部 460 卷）。它们有 `toc/LC/`、`toc/Y/` 文件和完整的卷 XML（授权声明是非商业使用），但 CBETA 自己的目录不显示。**决定：暂不收录**，不为它们生成节点，也不索引；`check` 把它们列为「未登记，忽略」。以后如果要收录，书目只能从 toc 和卷 XML 的 `teiHeader` 里取。
- **通用规则：菜单里有、但取不到真实内容的条目，保留在树里，解析时忽略即可**，不报错、不中断装配（例如链接指向的文件不存在、经号查不到、卷 XML 无法解析）。这种情况在用户自建的菜单里时有发生，`check` 负责把它们列出来供人工查看。

### A.5 作译者、朝代、典类

- 旧实现带一张人工整理的表，约 4800 部（经 ID 对应典类、标题、朝代、作译者）。典类分：经、律、论、经释、律释、论释、仪轨念诵法、传记、史、记录纪事、山志寺志、语录、序、目录、文献、音译、其他。分面中的「典类」「人物」「时域」就来自这张表。已转成 `data/bookinfo.json`（4826 条），转换脚本是 `tools/convert_bookinfo.py`。
- 表里没有的经才解析原始字符串：以空格切出朝代（长度小于 3，或属于乞伏秦、南北朝、宇文周），再用一组职责后缀（述、撰、譯、編修等）去掉职责得到人名，处理「等」「．」「、」分隔和括号注释。这种解析可能不准。
- 另有朝代表，给出各朝代的起止年份，并包含别称（如姚秦与後秦、北魏与元魏与後魏），可作为「时域」分面的归并和排序依据。已做成「时域表」（`data/dynasties.txt` 预设，格式 `名称<Tab>起年<Tab>止年<Tab>别称,别称`，约 50 行）：`core/src/dynasty.rs`。用户可在设置里编辑自己的表（存配置目录 `dynasties.txt`，同名行覆盖预设），可导入、导出文本。用处：①索引时时域按别称并入第一列的名字（后秦→姚秦，元魏、後魏→北魏）；②搜索页「时域」多一个「年代」排序（按起年）。改表后要重建索引才会合并。这是第一个「系统级键值表」；以后别的映射（人物别名、典类等）可以照同样的方式做。

### A.6 卷 XML（TEI P5 单卷版）的抽取规则

一个文件对应一卷，文件名形如 `T01n0004_001.xml`。样本见 `samples/cbeta/T01n0004_001.xml`，Python 参考实现见 `tools/ref_extract.py`。

| 元素 | 含义 | 抽取正文时 |
| --- | --- | --- |
| `teiHeader` | 经名、作译者、`idno`（藏经、册、经号）、缺字表 `charDecl` | 不入正文，作元数据 |
| `lb n="0159b05"` | 行标记，页码加栏加行号，是夹在正文中的空元素 | 记录文本偏移到行号的映射；只取 `ed` 等于藏经代码的那一套 |
| `pb n="0159b"` | 页栏分界 | 记录 |
| `p` | 段落，`xml:id` 末两位是段落在该行内的起始位置（不含标点，1 起算） | 记为锚点（`VolumeText::anchors`），也用来自动校验纯文本偏移 |
| `cb:juan`、`cb:jhead` | 卷头 | 入正文 |
| `cb:mulu` | 编者加的目录标签，原书不印 | **不入正文**（只用于大纲）。它的文字通常与紧随的 `head` 重复；实测去掉后段落锚点的不一致从 690 降到 175（T 藏抽样） |
| `app`、`lem`、`rdg` | 校勘：`lem` 是正文读法，`rdg` 是其他版本读法 | 取其中第一个 `lem`（没有时退到 `rdg`），忽略其余 `rdg` |
| `note` | 校勘注与脚注 | `place="inline"` 的是夹注，用全角括号包进正文；`type` 为 `cf1`、`orig`、`mod` 的跳过 |
| `g ref="#CB01979"` | 缺字引用，对应 `charDecl` | **一个缺字只输出一个字符**：单字的 normalized form > `mapping type="unicode"` > `mapping type="normal_unicode"` > PUA 码位；都没有时才用组字式或字名；找不到声明时输出 `@Declare@ID` |
| `space quantity="n"` | 空格 | 输出 n 个空格 |
| `cb:tt`（有无 `type="app"` 都一样） | 梵汉对照 | 只取 `zh-Hant` 的 `cb:t`，没有则取第一个 |
| `milestone`、`unclear` | 标记 | 整体跳过 |
| `byline` | 作译者署名行，位于正文开头 | 入正文 |
| 源文件中的换行与缩进 | 只是排版 | 丢弃，不当作正文 |

补充：

- `app type="star"` 是同一处异文的再次出现，里面也有 `lem`，要取。
- CBETA 修订过的读法，`lem` 的 `wit` 是 `【CB】`，大正藏原读法在 `rdg wit="【大】"`。默认取 `lem`。已做「底本读法」开关（阅读器头部，只改显示）：渲染时把 `【大】` 的 `rdg` 文字放进 `app` 的 `data-orig`（类 `app v o`，空读法用零宽空格），开关打开时用 CSS 隐藏原字、用 `::after` 显示 `data-orig`；命中位置按 `lem` 计，不受影响。
- **新式标点是 CBETA 加在原文上的一层，原书无标点**（`editorialDecl` 里有声明）。索引时去掉标点后，偏移就与原书的行内位置对应；多数行是 17 字，也有 16、15 字的行。
- **用段落锚点校验抽取**：`p` 的 `xml:id`（如 `pT09p0001a0501`）给出所在行和行内位置，等于免费的标准答案。`smart-library volumes <zip>` 对全部卷做这项检查：2025.Q1 共 231 万个锚点，98.8% 一致；去掉不收录的 Y 藏后不一致约 0.76%。
- **哪些字符不计入行内位置**（由锚点实测决定，不是猜的）：除原有标点外，`【】〖〗︵︶｀＇` 也不计入；`○ △ □ 〃 ※ ～ 〇`、制表符号（─│└┬ 等）、数字、拉丁字母都计入，保留在纯文本中。
- **缺字必须只占一个字符**：组字式（如 `[木*翕]`）占多个字符，会使行内位置偏移，也会给索引带来无意义的二字组。实测每个缺字声明都至少有一个 `mapping`（unicode、normal_unicode 或 PUA）。
- **悉昙字**（`SD-xxxx`）的「Character in the Siddham font」值（如 `一`、`乙`）是字体编码，不是文字，不能当正文；梵汉对照里一般取汉字那一侧。
- 已知不一致（约 0.76%，先记录，不影响 M0b）：CBETA 修订了文字的地方（`lem wit="【CB】"`），行内位置按大正藏原文（`rdg wit="【大】"`）计算，取 `lem` 时会差几个字；X 藏有大量行内位置超过行长的锚点（如一行约 20 字而位置是 55），可能是双行小字夹注另计，待查。
- `cb:docNumber`（如「No. 4 [No. 1(1), Nos. 2, 3]」）出现在正文最前，旧实现默认会把它包含在内，是否进入索引见第 12 节。
- **结构化渲染（已实现，`core/src/render.rs`）**：HTML 与文本抽取**共用同一次遍历**，正文字符按与 `plain` 完全相同的规则计数，所以检索命中（`plain` 偏移）可以直接在 HTML 里用 `<mark>` 高亮，`data-lb` 行标也正好落在 `lines` 所说的位置。2025.Q1 全部 21820 卷渲染后计数与抽取一致（`smart-library volumes <zip> --render`），约 3.4 ms/卷（抽取加渲染），共 108 万个校注标记、4361 张图（全部在 zip 中找到）。
- 渲染的结构映射：`cb:div` 到 div（class `t-类型`），`head` 到标题块，`byline`、`cb:juan`、`cb:docNumber`、`trailer` 到段，`lg`/`l` 到偈颂块与偈句（`caesura` 显示为空格，形成偈颂的两栏），`list`/`item` 到 ul/li，`table`/`row`/`cell` 到表格（`cols`、`rows` 合并），`entry`/`form`/`cb:def` 到词条，`cb:dialog`/`sp` 到问答，`hi`、`seg` 按 `rend`（bold、border、circle），`p cb:type="pre"`（科判）保留行内换行（`lb` 输出 `<br>`），`rend="text-right"` 右对齐。`style` 只保留以 em 为单位的 `margin-left`、`margin-right`、`text-indent`。
- 不计入正文、只在 HTML 里出现的：编注（`note` 带 `type`，`cf*` 除外，见下面「编注的显示方式」）；`app` 的各读法（`wit` 加文字，以「；」分隔）放进 `title`，有其他读法的 `app` 带 class `v`，并以 `data-n` 记下它的编注编号；读法是整段时（`lem` 或 `rdg` 里是 `head`、`p`、`lg` 等块级元素，例如某版本整品缺，T16n0663_004 的 `0358001`）不包进异文 span，直接把该读法按原结构渲染——否则整段都成了悬停 / 着色的对象，`title` 也会装下整段正文；与它同一 `n` 的编注说明被略去的内容，只按没有着色文字的编注点显示；梵汉对照另一侧放进 `title`（前端不用浏览器的单行提示，而是自绘浮层：正文读法在上，横线下面是其他版本，版本与文字两栏对齐）；`unclear` 显示为 ▆；`graphic` 显示图片。
- 图片：`url` 形如 `../figures/B/B06p0447_01.gif`，实际都在 bookcase 根目录的 `figures/` 下，取 `figures/` 之后的部分。桌面程序用自定义协议 `sl`（Windows 上是 `http://sl.localhost/figures/…`）从 zip 读取，只允许 `figures/` 下的文件。
- **编注的显示方式**（参照 cbeta-explorer，用户提出）：
  - 数据：一个编注点有同一 `n` 的几条相邻 `note`：`type="orig"`（底本原编注，如大正藏 `三藏＝法師【宮】＊`）、`type="mod"`（CBETA 编注，如 `三藏【大】＊，法師【宮】＊`；CBETA 自加的是 `add`），有时另有 `rest` 等；被改变的文字是同一 `n` 的 `app`。
  - 渲染：一个编注点输出一个标记 `<span class="note" data-note="序号" data-n="编号"><span class="nb-orig">原编注</span><span class="nb-cb">CBETA 编注</span></span>`（没有的部分不输出；orig、mod/add 都没有时才用其他类型的文字当 CBETA 编注）。序号不在文字里：阅读器用 `::before { content: attr(data-note) }` 画出（同 HTML 脚注的「（注）」），选中复制正文时不会带上。切换方式只换样式，不重新载入。2025.Q1 全部卷共 108.7 万个编注点，计数与抽取一致。
  - 阅读区工具栏（段落版式、CBETA 卷）六种方式，全局一种，保存在前端本地，默认「着色」：

  | 方式 | 编注点 | 悬停 |
  | --- | --- | --- |
  | 无 | 不显示 | 无 |
  | 原编注 | 直接嵌入原编注（小字） | 无 |
  | CB编注 | 直接嵌入 CBETA 编注（没有时用原编注） | 无 |
  | 数字标 | 序号（即 cbeta-explorer 的「✱标」，序号另有编号作用） | 序号上看 CBETA 编注 |
  | 着色 | 有其他读法的文字着色 | 着色文字上看 CBETA 编注、正文读法、其他版本读法 |
  | 着色+原编注 | 同上 | 另加原编注 |

  - 着色两种方式里，没有对应着色文字的编注点（如「增上寺經藏宋本闕此經」）显示一个淡的 ✱，悬停看编注。异文读法只在着色方式里悬停显示，不与数字标同时出现。
  - 悬停浮层：几组对齐的两栏（编注；正文读法；其他版本），组间画线；几个版本共用一个读法时写在一行（`【宋】【元】【明】：憋`）。指针离开文字后浮层停留 0.3 秒，可以移进浮层；在浮层里按下鼠标（选字复制）后浮层固定，点别处、按 Esc 或滚动才关闭。
- 缺字：正文与索引用单字符（见上），显示时若该字符是私用区码位（普通字体没有），改为显示组字式（如 `[木*翕]`），悉昙字显示转写，悬停显示缺字 ID。
- 其他：缺少 `xml:id` 的元素用「文档路径加选择器」的哈希生成稳定 ID；渲染结果按「文件名、修改时间、版本号」缓存。

- 导出：笔记引用到的图片放进包的 `attachments/`（去重）；导入：包里 `attachments/` 下合法名字的图片复制到目标知识库的附件目录。只读库的图片仍写成 `[图]`。图片按引用计数管理（`notes.db` 的 `attach_refs`：名字、计数、降到 0 的时间）：笔记新建、保存、删除时按内容里的 `attach:` 增减；粘贴时先登记计数 0；计数小于 1 的图片至少留 24 小时（编辑中的撤销可以恢复），程序运行时每 6 小时清一次，设置里的「清理缓存」按 1 分钟清。

**笔记编辑器（2026-11）**
- 笔记标签的编辑区有两种方式（工具栏「排版 | 源码」，选择记在本地存储 `note.editor`）：排版 = Milkdown Crepe 所见即所得（`NoteEditor.svelte`，第一次编辑时才载入，约 1.1 MB）；源码 = 原来的文本框。内容始终是 Markdown，两种方式共用同一份草稿，切换时重新载入。
- 排版方式只开启阅读器能显示的功能：标题、列表、引文、粗体斜体、链接、图片、脚注；关闭表格、公式、代码编辑器、顶栏。颜色和阅读字体用程序的变量。图片：粘贴、拖入或「/」菜单上传都交给 `note_attach`，在文档里是 `attach:<名>`，显示时由 `proxyDomURL` 换成附件地址。
- 排版方式不用 Escape 取消编辑（Escape 要用来关它的菜单），只能点「取消」。
- 试验结果（往返 Markdown）：`-` 列表改写成 `*`，硬换行改写成行尾 `\`，`&` 等写成 `\&`，图片的说明文字被换成缩放比例，脚注定义之间多一个空行；脚注和 `smartlib://` 链接保留。`markdown.rs` 因此认得反斜杠转义和行尾反斜杠（`unbackslash`）。

**脑图笔记（2026-11）**
- 类型：自建知识库里的笔记有 `content_type`：`md`（文档）或 `mindmap`。脑图的内容是 Mind-Elixir 的数据 JSON（`{"nodeData": {id, topic, children, hyperLink, tags …}}`）。新建：「＋」或笔记节点右键 → 笔记…，对话框里选「文档笔记 / 脑图」；目录树里脑图用脑图图标。
- 阅读 / 编辑：脑图标签直接用 Mind-Elixir 显示并编辑（`MindMapView.svelte`，第一次打开时才载入；中文右键菜单；跟随明暗主题），改动后约 0.8 秒自动保存，Ctrl+S 立即保存，关闭标签时补存。节点的链接（`hyperLink`）是 `smartlib://` 时点击回到原文位置，其他链接不跳转。
- 摘录：「加入笔记」对话框里选脑图，选中的文字成为根节点下的新节点：文字作为话题（最多 160 字），`hyperLink` 是来源地址，标签是来源说明（`mindmap_add_clip`，已打开的脑图标签随后重新读取）。给脑图追加 Markdown 文字（`note_append`）会报错。
- 检索：建索引时脑图的所有话题连成文字进索引（`mindmap::text`）；脑图没有段落号，结果里不显示行。
- 导出：脑图在包里有两个文件：`docs/N.md` 是缩进列表形式的大纲（别的软件也能读），`docs/N.mm.json` 是脑图数据，manifest 节点用 `mindmap` 字段指向它；导入时按它还原成脑图笔记。

**脑图插件（2026-11）**
- `@mind-elixir/node-menu`（5.x，与 mind-elixir 6 兼容）：选中节点右侧的样式面板（字号、粗体、文字和背景颜色、标签、图标、链接、备注）；`mind.locale = "zh_CN"` 后是中文（「Memo」仍是英文）。

**笔记不再分阅读和编辑（2026-11）**
- 自建知识库的文档笔记直接在排版编辑器里打开（它同时是阅读器），没有「编辑 / 保存 / 取消」；改动后 1 秒自动保存，Ctrl+S 立即保存，关闭标签或窗口时补存，标题栏旁显示「未保存 / 已保存」。编辑器刚载入时自己改写文字不算改动（只有载入之后的改动才保存，避免打开就改写了笔记）。不再有「原书行」「行号」「目次」下拉框等阅读器版式；工具栏只有「排版 | 源码」、加标签、在目录树中定位。
- 阅读器的功能怎样带过来（`NoteEditor.svelte`）：搜索命中用 CSS 自定义高亮（`::highlight(sl-hit)`）标出并滚到第一处；行号 `¶n` 在编辑器里指第 n 个标题、段落或列表项，用来跳转和记录阅读位置（和 Rust 渲染器的段落号不完全一致，引文的多行 `>` 对不上，所以摘录来源链接优先用 `q` 的文字）；摘录的来源链接点一下就跳；选中文字的右键菜单有复制、四种检索、页内查找、加入笔记、书签、收藏。没有选中文字时是浏览器自己的菜单。
- 笔记在别处被改（比如另一处摘录加入）：打开着的标签，摘录直接加进编辑器并保存；其他情况（改名、外部写入）标签重新读取。没有「只读」保护，误改靠编辑器的撤销（Ctrl+Z）。
- 只读库（CBETA、HTML 文章、外部文件夹）仍用阅读器；外部文件不会被改。

**新建入口、日记、白板（2026-11）**
- 新建：去掉「新建笔记」对话框（`NoteDialog` 已删）。「＋」菜单、知识库右键、笔记节点右键都直接列出「新建笔记 / 新建脑图 / 新建白板」，点一下就建好并打开，名字自动取「笔记 n」「脑图 n」「白板 n」（n 取同级里没用过的最小数字，`NotesStore::free_title`），之后随时重命名。右键节点时建在该节点下面（菜单上不再写「子」，因为没有「同级」入口）；从「＋」建时放在目录树里选中的笔记下面，没有选中则放进第一个非日记的自建知识库；一个自建知识库都没有时自动建「我的笔记」。后端 `create_note_at(default_lib, position, title?, kind)`，`kind` 是 `md` / `mindmap` / `whiteboard`，`title` 可省。
- 日记：自建知识库「我的日记」（`diary::LIBRARY`），第一次用到时自动建。日记就是普通 Markdown 笔记，位置按日期：`2026年` › `11月` › `2026-11-08`（`diary::path_of`）。日期由界面取本机本地日期传给后端（`diary_today(date)`），后端没有时钟。三种方式用到今天的日记：「＋」菜单「今日日记」或 Ctrl+J（`shortcuts.js` 的 `diary`；是窗口内快捷键，不是系统级全局快捷键）；展开目录树里当前月的节点时先确保今天这篇存在；阅读器和笔记编辑器选中文字的右键菜单「发送到今日记」，内容前加一行加粗的时间 `**HH:MM**`，再接摘录（和「加入笔记」同一种带来源链接的引文），今天的日记正在编辑时追加到编辑框里。
- 白板：`content_type = whiteboard`，内容是 Excalidraw 的场景 JSON（`serializeAsJSON` 生成，图片作为 `files` 内嵌）。`WhiteboardView.svelte` 把 React 组件挂到普通元素里（`react`、`react-dom`、`@excalidraw/excalidraw` 0.18，第一次打开白板时才载入），只在图形真的变了时（元素 `id:version` 或图片集合变化；平移、选中不算）约 1 秒后自动保存，Ctrl+S 立即保存，关闭标签补存。字体不走 CDN：`vite.config.js` 的插件把包里的 `fonts` 目录开发时放在 `/excalidraw-assets/fonts/`，构建时复制到 `dist/`，`EXCALIDRAW_ASSET_PATH` 指向那里（离线可用，安装包大约增加 14 MB，需要时可以只留常用字体）。
- 检索与导出：建索引时白板里所有文字元素按从上到下、从左到右连成文字（`whiteboard::text`）；数据包里和脑图一样两个文件，`docs/N.md` 是文字列表，`docs/N.wb.json` 是场景，manifest 节点用 `whiteboard` 字段指向它。白板不能追加 Markdown，也不出现在「加入笔记」的追加目标里。
- 安装依赖时 `npm install` 会因为 `@mind-elixir/export-html` 的 peer 依赖写的是 mind-elixir 3.x 而报冲突（原有问题），要加 `--legacy-peer-deps`。


**菜单整理与重命名（2026-11）**
- 目录树右键菜单按功能分组，组与组之间用分隔线：新建（笔记 / 脑图 / 白板）、编辑（重命名、上移、下移、删除）、复制（原文件路径、目录树路径）、搜索（从这里搜索标题 / 全文；知识库菜单里还有建立 / 重建索引）、标签、导入 / 导出、知识库本身（重新绑定、删除 / 解除绑定）。多选菜单也按复制、搜索、导出排列。「＋」菜单里原来的「知识库…」改叫「新建知识库…」。
- 知识库可以重命名（右键「重命名…」，命令 `rename_library`）。只改登记表里显示的名字：绑定的外部库（数据包、文件夹）本身不动；名字不能为空，也不能和别的知识库重名。注意：日记库靠名字「我的日记」找到，改名后下次用日记会另建一个「我的日记」。
- F2 重命名：焦点在目录树里的知识库时改知识库名，在笔记节点上时改笔记名；焦点在别处（不在输入框、编辑器、白板里）时改最近从目录树打开的那篇笔记。只读知识库里的节点不能改名。
- 白板的右键菜单靠近边缘时，`WhiteboardView.svelte` 用 `MutationObserver` 把 `.context-menu` 平移回白板范围内。
- 目录树状态：右键点开菜单的节点（或知识库）加浅底色和细边框（`marked`），菜单关闭后消失；当前阅读标签对应的节点（已载入的树里能找到时）左边加粗线、字体加粗（`active`，由 `ws.current` 推出）。知识库菜单里「导入、导出、绑定知识库、删除 / 解除绑定」放在同一组。
- 白板：右键菜单伸出白板范围时，浏览器会把 `overflow: hidden` 的外层面板滚动一点（面板「上移」），所以白板外层用 `overflow: clip`，并在捕获到包含白板的元素滚动时把它们的滚动位置还原。
- 白板右键菜单的位置：Excalidraw 自己算位置时把窗口坐标和白板坐标混在一起，放进停靠面板后会离开鼠标（贴着底边弹出）。`WhiteboardView.svelte` 记下右键位置，菜单出现后重新摆放：默认在鼠标右下，下面放不下就翻到鼠标上方，右边放不下就翻到左边，最后限制在白板范围内；`scroll` 事件（含整个文档）里把包含白板的元素的滚动位置还原。
- 排版编辑器（Milkdown / Crepe）的功能：标题、列表、引文、图片、表格（Table）、代码块（CodeMirror，带语法高亮）、选中文字的工具条、链接提示条（LinkTooltip，默认开启）；公式（Latex，`$…$` 和 `$$…$$`）、顶栏（TopBar）也开着；只有 AI（需要接语言模型服务）没开。公式在 Markdown 里是 `$` 括起的文本，建索引时当文字读，单独一行的 `$$` 忽略。表格和代码块仍是 Markdown 文本（`| a | b |`、围栏代码），`markdown.rs` 读它们建索引：表格每行是一个段落，单元格用 ` | ` 隔开，表头下的分隔行忽略；代码按行成段。
- 脑图：重启后没有显示过的标签（隐藏时没有尺寸）里的脑图要等到板子第一次有尺寸才创建（`ResizeObserver`），否则节点布局错乱、连线丢失。右键只给菜单，不再拖动画布；按住中键拖动画布（和白板一致，`MindMapView.svelte` 在捕获阶段拦截指针事件，用 `mind.move`）。
- 在目录树中定位自建知识库的笔记：笔记的子节点是懒加载的，重启后树没载入，所以用 `note_chain` 取得从顶层到该笔记的 id 链，逐层载入后再选中（`findNoteNode`）；复制目录树路径也用它。
- 阅读器工具栏（每个阅读器上方的一条，新功能都往这里加）：左边是文档标题，前面加定位图标，图标和标题合成一个链接（`TitleLink.svelte`），点击在目录树中定位；原来笔记和 CBETA / HTML 阅读器上单独的定位按钮去掉了。CBETA / HTML 阅读器的标题带卷名。笔记、脑图、白板的工具栏右侧都有「加标签」按钮。
  四种视图（CBETA / HTML 阅读器、笔记、脑图、白板）的工具栏共用 `app.css` 里的 `.view-bar`：内边距 8px（四边等距）、控件间距 8px、字号 14px，标题（`TitleLink`）随之统一；工具按钮 `.tool-btn` / `.ai-btn` 和分段按钮 `.seg` 的样式也只在这里定义，各视图不再各写一套。
- 脑图右键菜单：Mind-Elixir 的菜单层盖满整个画布，只有左键能关掉，所以在别的节点上右键点到的是菜单层。`MindMapView.svelte` 在捕获阶段接住菜单层上的 `contextmenu`，关掉菜单，再把右键交给下面的元素重新触发。
- 目录树：知识库名右边的「未建索引」「索引过期」是可以点的（点击建立 / 重建索引，建好后提示自动消失）；节点鼠标悬停时整行从左边界到右边界都有底色（和选中、右键一致）。CBETA / HTML 阅读器工具栏：左边是定位链接、卷、目次，功能性的控件（段落 / 折行 / 折页、行号、编注方式、命中数、标签）靠右。

**AI 助手（2026-11）**
- 开关与多模型预设：设置对话框「AI 助手」区块提供总开关（`settings.aiOn`，默认关闭）和多个模型预设列表（`settings.aiPresets`、`settings.aiActiveId`）。每个预设包含名称、接口协议（`openai` 兼容 `/v1/chat/completions` 或 `anthropic` `/v1/messages`）、接口地址（`baseUrl`）、API Key、模型名称、自定义系统提示词，支持一键「测试连接」。AI 侧栏与独立会话窗口顶部均可随时下拉切换当前激活的模型预设。
- 后端流式网关（`app/src-tauri/src/ai.rs`）：基于离线已有的 `reqwest`（`rustls` + `stream`）与 `futures-util`（`Abortable`）实现 OpenAI / Anthropic SSE 流式解析，通过 Tauri `Channel<AiEvent>` 向前端推送增量文本（`delta`、`reasoning`、`done`、`error`），支持中途随时停止生成（`ai_abort`）。
- 会话历史独立持久化（`core/src/ai_chat.rs`）：存储在数据目录 `<data_dir>/ai_chat.db` 的 `ai_sessions` 表，按 `scope_kind`（`doc` / `search` / `chat`）与 `(lib, path)` 关联文档，不修改任何知识库源文档。打开文档侧栏时自动恢复该文档最近一次会话；支持在「历史」抽屉中按当前文档或全部会话查看、恢复、删除单条会话，或在设置中一键清空全部会话历史。笔记重命名/移动或知识库解绑时同步更新或清理关联记录。
- 触发方式与多文档引用（`AiPanel.svelte`）：
  1. **主窗口统一右侧 AI 侧栏（`App.svelte`）**：参照 IDE（VS Code / IDEA）的统一辅助栏模式，在主工作区右侧提供全局统一的 AI 会话面板（可拖拽分隔条调整宽度，状态记在 `ai.open` / `ai.width`）。切换主区任意标签页（只读阅读器、Markdown 笔记、脑图、白板、全文搜索页）时，右侧会话保持不断开，且动态感知当前激活标签页的文档内容或搜索结果，支持通过「`+固定引用`」将当前文档固定进引用列表后再切去其他文档协作。
  2. **各视图快捷联动**：所有阅读器/编辑器工具栏与搜索页工具栏均提供「AI 助手」按钮，点击打开/收起右侧统一 AI 栏；选中文字右键菜单（「发给 AI 助手」「AI 解释选中文字」「AI 润色 / 续写」「AI 编写创新方案」）与脑图节点右键菜单（「AI 扩充此节点…」）会自动唤起右侧 AI 栏并把选中片段及来源文档加入会话。
  3. **Milkdown 排版编辑器行内 AI**：当 `aiOn` 开启且当前预设配置完整时，`NoteEditor.svelte` 自动启用 `@milkdown/crepe` 内置的 `Crepe.Feature.AI`（斜杠菜单与选中浮动工具栏 AI 指令），复用后端流式通道。
  4. **独立 AI 窗口与历史切换**：右侧 AI 栏顶部支持通过「＋新对话」与「历史」抽屉在不同工作会话间随时切换，也支持「新窗口」将当前会话弹出为独立窗口（`AiChatWindow.svelte`）或停靠回主窗口工作区。
  5. **跨库多文档引用**：无论在何处对话，均可通过「`+ 引用文档`」按钮、在输入框键入 `@` 调出标题快搜，或从左侧目录树直接拖拽一个或多个节点到 AI 面板，将被引用的知识库文档正文（`ai_doc_text`）注入会话上下文。
- 理解与编辑可读写文档：
  - **Markdown 笔记**：AI 回复代码块或正文可一键「追加到笔记」或「替换笔记内容」，也可将任意回复「存为新笔记」。
  - **脑图（Mind-Elixir）**：`core/src/mindmap.rs` 新增 `from_outline_or_json`，支持将 AI 输出的 Markdown 缩进列表/标题大纲或 Mind-Elixir JSON 解析为脑图节点树；在脑图侧栏可一键「追加为选中节点的分支」或「替换整张脑图」。
  - **白板（Excalidraw）**：`WhiteboardView.svelte` 支持让 AI 生成 Excalidraw 图元骨架 JSON（或将列表自动转为带连线的流程图框），通过 `convertToExcalidrawElements` 一键「追加到白板」或「替换白板」。
- **后续规划（AI 工具调用 / Agent 能力，待实现）**：
  - 当前 AI 助手仅支持被动读取当前激活标签页上下文、用户显式引用的多篇文档，以及通过界面按钮将回复写入当前激活的可读写文档或另存为默认位置的新笔记/脑图；尚未接入大模型的 Tool Calling（函数调用）循环。
  - 后续可扩展工具调用机制（OpenAI `tools` / Anthropic `tool_use`），使 AI 助手在会话中按需自主调用程序内部能力（写操作需带确认或可撤销提示）：
    1. **检索与读取**：自主调用全文搜索（`search`）、标题快搜（`quick_search`）、目录树浏览（`tree_root` / `tree_children`）与文档正文读取（`ai_doc_text`）。
    2. **历史与收藏标签**：查询最近阅读历史（`recent_list`）、查询/添加书签与收藏（`marks_list` / `mark_add`）、读写节点标签（`node_tags_get` / `node_tags_set`）。
    3. **文档与目录结构管理**：在内部知识库的指定节点下新建不同类型文档（笔记 / 脑图 / 白板，或直接写入/追加到指定文档 `note_append` / `save_note`）、在读写模式的本地文件夹知识库中新建文件夹与文档（`folder_mkdir` / `folder_create` 等）。
